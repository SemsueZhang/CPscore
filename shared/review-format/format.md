# 题面与题解共用格式协议

题面与题解使用相同的格式规则、规范类别、独立位置计数、LLM 复核接口和格式扣分。各 Skill 随包提供同源的 `scripts/format_lint.py` 与本协议，单独复制技能目录即可使用，不依赖另一个 Skill。

先确认材料语言、源码／发布形式和明确适用的平台规范。特定平台的图床、长代码折叠等要求只在适用时检查；不能把洛谷题解投稿资格、来源披露或题解正文要求扩展到所有题面。外部图床候选可凭不适用的规范证据排除。

格式优先静态检查，审核 LLM 核验 Warning、未验证范围及静态规则遗漏，再交脚本合并。算法、任务规格、证明、教学、内容与来源资格分别由对应技能审核。AIGC 文本倾向按对应技能的表达协议报告，不能把概率判断当作已证实的 AI 创作来源，也不另作格式扣分。

内容审核与格式审核分开完成、分开给结论后再汇总。脚本只辅助格式，LLM 对脚本没有覆盖的部分负审核责任；候选为空、格式扣分足以拒绝、候选已全部处理或单元测试通过，都不能代替完整的内容审核和格式补查。

## 文字与 Markdown

| 对象 | 协议要求 |
| --- | --- |
| 标点与空格 | 中文叙述用全角中文标点并补全句末标点。中文与英文、数字和行内公式之间留一个半角空格，中文标点旁不另加空格，中文词内不插无必要的空格或全角空格。缺空格与多空格分别核对。 |
| 数学模式 | 数学量、运算式、运算符及参与运算的常数用 LaTeX；普通词语、人名、题名和算法名不用。一个表达式放在同一环境，独立公式用行间环境；说明用 `\text`，字符串用 `\texttt`，合法说明中的中文不一律判错。 |
| 标题与列表 | 用一至四级标题，不用标题堆砌强调、步骤或无关内容。无序列表用标记，有序列表用数字加点，标记后留空格，核对嵌套、缩进、顺序及实际显示。 |
| 代码与链接 | 程序片段及字符串用行内代码，成段代码用代码块；不用代码样式强调普通叙述。链接和图片使用对应 Markdown 语法，核对分隔与可用性。 |

必要空白不算冗余：代码缩进、样例／字符串空格、列表缩进、表格源码对齐、行尾硬换行、TeX 内部空白及渲染器生成的数学间距。区分源码冗余和实际显示异常，例如 `结论 $x$ 。` 应删标点前空格，`中文  English` 应合并边界空格。

## 数学记号

定义、量词、取整的数学含义、边界及论证由各技能的内容审核核验，避免将语义问题重复归入格式。下表的排版要求只适用于公式；程序中的合法判等、取模和成员访问不套用公式规则。

| 对象 | 协议要求 |
| --- | --- |
| 赋值、推导与判定 | 赋值用 `\gets`／`\to`，逻辑推出用 `\Leftarrow`／`\Rightarrow`。数学比较用数学关系符号，不照搬程序判等。艾佛森括号的真假值明确，不将单向推出写成等价。 |
| 除法与取整 | 区分分数、整数商及上下取整，如 $\lfloor a/b\rfloor$、$\lceil a/b\rceil$；取整覆盖整个所需表达式，核对分母非零和边界。 |
| 取模与同余 | 余数用 $a\bmod b$，同余用 $a\equiv c\pmod b$，不混用。 |
| 集合、区间与结构 | 区分属于／包含、空集／零、开闭端点；对象分量用上下标，不用程序成员访问。位运算用 `\operatorname{and}`／`or`／`xor`，改用集合语言只是建议。 |
| 上下标与大数 | 多字符下标和指数正确分组，大数用科学计数法，变量名与大小写一致。 |
| 复杂度 | 时间和空间的大 $O$ 都省去固定乘法因子，$O(2n)$、$O(3n\log n)$ 即使随后化简仍属格式问题。操作次数推导可保留常数；$O(1)$、$O(n^2)$、$O(2^n)$ 不在此列。变化的值域／字符集等参数用字母表示，不得删去真实开销。 |
| 函数与大型运算符 | 使用正确的加减、乘除、比较、整除符号，约定函数名用 `\gcd`、`\max`、`\min`、`\log`、`\det` 等正体，其他函数用 `\operatorname`。求和、乘积、并交用相应大型运算符，哑变量、范围、被作用项及多层依赖明确。 |
| 数学结构与定界 | 分数、根号、上划线、集合括号用相应命令，分组、作用域及定界匹配，不让排版改变含义；区分绝对值、范数、整除及条件分隔，合法等价写法均可。 |
| 省略与多行 | 省略号用 `\dots`／`\cdots`／`\ldots`，矩阵方向用 `\vdots`／`\ddots`，波浪线用 `\sim`。连等用 `aligned`，分段用 `cases`，矩阵用 `bmatrix`，检查闭合、换行、对齐、维度、各行条件与边界。 |

## 按材料用途适用的展示要求

仅在材料包含对应内容时适用。题解引用题面或列出这些内容时使用相同要求，不强制题解重复题面。

- 远程评测题的题名通常保留原文，已有知名书籍译名可例外。
- 输入输出的同类句式统一，并列输入变量放在同一数学环境，固定输出字符串用行内代码。中文序号属于建议。
- 完整题面中的取模要求在题目描述和输出说明两处写明，模数和对象保持一致。缺一处重复展示按格式处理；模数或是否取模无法确定时交规格审核。
- 类型放在输入说明，范围通常集中在说明或提示。有效位较少且不小于 $10^5$ 的数用科学计数法，不同范围分公式并用全角逗号隔开，相同范围可合并。无部分分时，某变量的范围可放在输入格式中。
- 实际采用捆绑测试时，加粗声明“本题采用捆绑测试”。表格和 Subtask 无序列表属于建议。计分方式未明确时记录待核验，不自行指定捆绑计分。

上述展示约定由 LLM 核验。已归入缺少数学环境、大数字表示、标点等类别的错误使用原类别；其余明确展示违规通过 `document_layout` 类别提交补充发现。字段缺失、范围错误、计分歧义属于规格审核，不重复算格式错误。缺失声明以应出现处的现有标题或邻近原文绑定位置，不伪造不存在的摘录；同一缺失声明只算一个位置。

## 格式计数与定级

格式优先静态检查，LLM 核验脚本不能确定的部分，并通过复核接口提交证据。统一采用 `format_lint.py` 合并后的 `format_assessment`，不在报告中另加一套格式计分。

| 单篇文章中同一格式类别的已确认独立位置数 | 定级与扣分 |
| --- | --- |
| 0 且没有未确认范围 | 不扣分 |
| 1～2 | Major −2，同类只扣一次 |
| 至少 3 | Fatal −10，同类只扣一次，不再叠加 Major |

类别由脚本的 `CATEGORIES` 定义。例如正文和公式边界的缺空格统一计数，缺空格与多空格分别计数。一处空格被多个检测分支命中只算一处；一个公式两侧各缺空格则是两个位置。不同文章不合并凑够三处，同一路径重复传入不增加次数。

未经 LLM 证实的 `Warning`、未支持语法和未验证范围不能当成已确认次数。LLM 排除的候选不计分，证实的按原独立位置计数，无法核实的仍按严格通过策略判“未通过：无法确认”，每类记一次 Major；同类别已有 Confirmed 定级时不额外叠加扣分。图片文字、复杂宏或目标显示必须实际取得并核查材料，不能仅凭已读候选就标为已验证。

工具未能运行时，由 LLM 核验已有材料并按同一类别和独立位置规则计分。仍无法完成的必查范围才记录核验缺口 Major，不因缺少 Python 自动处罚。不得把环境故障说成稿件本身的格式违规。

## 格式工具的覆盖与边界

`format_lint.py` 使用 Python 3.8+ 标准库读取 UTF-8 Markdown，不编辑、不联网、不运行模型。输出静态发现、复核候选和未验证范围，可合并审核 LLM 的来源绑定裁定。它只计算格式扣分，不计算题面或题解总分。

| 可执行规则组 | 检查内容 |
| --- | --- |
| `TXT001`～`TXT006` | 中英／数字间距、引号括号等中文标点旁空格、全角字符、明确句式的句末标点，以及段内软换行 |
| `MD001`～`MD006` | 标题层级和空标题、步骤式标题线索、列表标记、列表归属、代码定界 |
| `MD007`～`MD014` | 代码样式用途、裸 URL、图片附加链接、图床、长代码折叠、强调线索与定界、扩展容器开闭范围 |
| `MATH001`～`MATH005` | 公式边界间距、数学定界、可识别的裸数学式、多余数学环境，以及通过运算符串接的拆分公式 |
| `DOC001` | 按材料用途适用的展示约定，由 LLM 提交补充发现，不作静态自动判定 |
| `TEX001`～`TEX015` | 环境／花括号闭合、已知命令、简单必要参数与定界符、函数正体、公式中文与标点、程序式记号、省略号、复杂度固定因子、连等、上下标、大数字及独立公式环境 |

单次词法扫描按上下文隔离代码、公式、链接地址和图片，保留链接可见文字。公式中的数组方括号不会再被当作引用式链接；已识别的普通标记也不能隐藏文字边界。代码和数学环境内部不套用普通中文排版。合法的文本命令、表格对齐、结构缩进与硬换行有专门排除。

格式引擎自 v2.1 起按 `commonmark-softbreak-whitespace` 模型处理段内换行。能证明换行在中文标点旁生成多余空格时，`TXT006` 为 Confirmed，`evidence` 记录模型及两侧字符；其他断行意图不明的情况仍为 Warning。模型推导不等于目标页面的渲染实测。

连续至少三条只有编号动作句、没有章节正文的标题可由脚本确认为步骤式标题；单个长标题等含糊用法保留 Warning。明确的更新／初始化赋值与定义、条件等式分开检查。算法概念名在明确的定义或分类句式中误用代码样式可确认，真实字符串和程序片段保持隔离。

v2.2 识别 HTML 字符引用并映射回源码位置，覆盖扩展汉字与特殊空白，校验链接目标及可选标题。数学参数检查接受分组和单 token 参数、根号简单可选指标、`operatorname*`、数组列格式及对齐组数。未知宏／环境、无分组的复合取参、复杂指标与列格式、颜色及上下限修饰等上下文敏感语法留给 LLM。命令清单对照 [KaTeX 支持表](https://katex.org/docs/support_table.html)及[语法示例](https://katex.org/docs/supported.html)核对（2026-11-14），不代表洛谷当前配置实测；支持名字也不等于任意参数均合法。未知 HTML 子文字整体保留未验证，避免把隐藏内容当成可见排版事实。

**边界不等于通过**：本脚本不是完整 Markdown／LaTeX 渲染器。宏支持、未知多字母串是函数还是隐式乘积、含糊的标题／强调／列表用途、代码是否为字面字符串、长代码是否需要折叠、词内空格、科学记数法阈值等仍输出 Warning。80 行只是长代码线索，不冒充洛谷公布的长度标准。图片文字、复杂 HTML 和部分容器的未验证范围进入 `skipped`。

Warning 与未验证范围交审核 LLM 核验，不调用独立 Agent。证实问题、排除候选或保留无法确认均须依据可取得的原文和适用规范。脚本对剩余未确认项按[格式计数与定级](#格式计数与定级)计分，不把三条警告算成三处确定错误。数学符号所表达的真实取整、范围或推理是否正确属于数学内容审核，不能假称正则已证明数学语义。

JSON `schema_version=2` 保持兼容，另有 `linter_version` 和 `render_model` 标识规则实现与模型。`findings`、`skipped` 保留原始扫描，`review_candidates` 给出复核候选；`effective_findings`、`effective_skipped` 是应用裁定后的材料，`format_assessment` 对其计分。单篇 `files` 同时保留 `static_format_assessment`，便于追溯。`groups` 提供类别、次数、位置、级别、扣分和证据性质；格式结论为 `pass`／`non_compliant`，未执行扫描为 `not_assessed`。退出码 0 表示执行成功而非格式通过，2 表示环境／输入／裁定记录失败；部分文件失败仍保留成功扫描。

`--check` 仅检查环境，`--rules` 输出机器可读规则表，两者都不能当作稿件格式已通过。Python 不可用时不安装依赖，由 LLM 继续检查可取得的材料，明确剩余范围；没有 Markdown 时不能声称已验证源码。

## LLM 格式复核接口

先扫描，再逐项阅读 `review_candidates` 对应上下文，并主动检查脚本未报告的原文。LLM 补查不以出现 Warning 为前提：数学对象与普通词语的用途、上下文中的中文括号、段落和列表归属等未获静态覆盖时，都需结合全文核验。对图片、HTML 或渲染支持的裁定还要实际读取相关材料；源码片段只用于绑定位置，不足以证明外部内容。LLM 裁定不会因 JSON 校验通过而自动变成数学或渲染事实。

**允许新增和重新归类发现**：原 Warning 的类别不适用而该处存在其他格式问题时，排除原候选，再将正确类别及精确证据写入 `additional_findings`，在理由中说明重新归类关系。未被脚本报告的问题也直接使用该字段。选择 `--rules` 给出的适用类别，不能只在文字报告补一句却漏掉合并和计分；没有实质新问题时不强凑补充发现。

例如，算法名被误当成待排正体的数学函数时，排除字体警告后还要检查是否误用了数学环境；中文旁的半角括号即使没有候选，也应核对其是否为普通说明而非程序语法。重新归类不允许借接口撤销静态 Confirmed；若发现静态误报，应修正规则后重扫。内容语义问题另交内容审核，同根因在最终总分中只取最高级别，不改写原始扫描事实。

临时 JSON 顶层只含 `files` 数组，每个记录绑定扫描输出中的完整 `file` 和 `sha256`：

```json
{
  "files": [{
    "file": "/path/to/material.md",
    "sha256": "复制本次扫描的摘要",
    "decisions": [{
      "candidate_id": "复制本次候选 ID",
      "verdict": "dismissed",
      "reason": "说明上下文和适用规范为何允许此写法",
      "evidence": [{"offset": 0, "end_offset": 2, "excerpt": "原文"}]
    }],
    "additional_findings": []
  }]
}
```

- Warning 候选使用 `confirmed`／`dismissed`／`unverified`。未提交候选保持原状，不默认通过。
- scope 候选使用 `reviewed`／`unverified`。`reviewed` 仅表示该范围已核查，发现的错误另放 `additional_findings`；不能把真实存在的源码错误通过“已核查”消除。
- 每条裁定须有非空理由和精确原文证据，与候选范围相交。偏移为解码后 Unicode 字符的零起点、左闭右开区间，不是 UTF-8 字节位置。输入以 UTF-8 读取，剥除开头 BOM，保留 CR／LF 原换行后计算摘要。
- 补充发现含 `category`（`--rules` 中的规范类别，不能为 `coverage`）、`offset`、`end_offset`、`excerpt`、`position`、`standard`、`reason`、`evidence`。`position` 为独立错误的规范位置：缺空格取边界右侧起点，其他错误取错误起点，公式整体错误取公式正文起点；必须落在摘录范围内。同一物理位置不能换锚点增加次数。先与静态发现的 `occurrence_key` 核对，再合并。
- 静态 Confirmed 不能经此接口撤销；怀疑误报应修复规则并重扫。禁止填写 severity、次数、扣分等外部结果。

运行 `python3 scripts/format_lint.py --decisions /tmp/review.json /path/to/material.md`。脚本先重新扫描，再校验整个 JSON 批次；旧摘要、伪造 ID、证据不符、重复裁定、非法字段等均拒绝整批应用，保留静态结果并标执行错误，不能产生假通过。校验负责来源一致性和计数，裁定的语义真实性仍由审核 LLM 负责。

本协议的共用排版要求取自仓库已核对的《洛谷主题库题解规范》格式条款（原核对日期 2026-11-13），按材料和发布环境确定适用性。v2.3 将原题面的输入输出、范围与子任务展示要求纳入共用协议，`DOC001` 由 LLM 核验，不代表新增了静态检测能力。
