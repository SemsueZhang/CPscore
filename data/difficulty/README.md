# Difficulty 数据与评测边界

这里是维护与评测资料，不是评分 Skill 的上下文。

| 文件 | 用途 |
| --- | --- |
| `expert/cases.jsonl` | 专家反馈、材料路径和指纹、标签来源、家族、相邻比较、模型错误及人工复核状态 |
| `expert/experiences.jsonl` | 可编辑的候选、已确认和已拒绝经验，包含条件、局限和反例检查 |
| `development-registry.json` | 永久保留的开发暴露身份与材料指纹，供独立评测隔离检查 |
| `luogubench87-development.json` | 旧 87 题的冻结材料与解法身份映射，只允许开发诊断 |
| `history/index.json` | 原 Skill、原数据、历史结果的哈希及来源目录 |
| `history/<run>/` | 原始报告、指标、预测及已有 Skill 快照的逐字副本 |
| `diagnostics/20261114-undistilled-why/` | 原实验的统计、逐题、重复波动与局部消融诊断，含局限和未验证解释，不进入正式 Skill |

原 87 题、旧锚题、五个已确认的单轴反馈，以及 CF/AT 同题元数据（含旧换算留出）均保留开发/历史身份。平台元数据的 holdout 只针对当时的换算拟合，不是新版内容评分的独立测试题。当前没有新独立评测集或正式专家通用经验。已完成一次[未蒸馏新版的 87 题配对开发诊断](evaluations/20261114-v2-undistilled-sol-high/Report.md)，保存在 `evaluations/`，不改变这些题的开发身份。

近变体家族还需要人类整理。`unreviewed:<problem_id>` 只是未审查身份占位，不表示近变体已隔离。不能以题号不同或哈希不同断言家族独立。新独立集必须人工检查题面、题解、代码语义一致性、满分路线与已有开发题的家族关系，在清单记录确认人、日期和具体说明。指纹只能防止确认后换错文件，不能证明算法正确或语义同题。

注册表通过 `expert_data` 在准备评测时动态纳入新增专家案例及家族，随后冻结为实验快照。其他新开发来源、见过的评测题及其别名、家族也必须由维护者补入注册表。难度标签单独保存在维护者的 labels 文件中，不写入输入、split 或模型请求。题解正文中的难度暗示、来源和身份仍须在数据制作时盲化并人工复核，JSON 字段白名单不能自动消除文本泄漏。

独立集应在修改 Skill 之前锁定。按题族隔离，而不是按题号随机切分。保持标签不向评分过程开放，完成整套预测并冻结后才计分。查看错误并用于蒸馏之后，该集降为开发诊断，新版本需要另留独立集。公开旧题可能存在预训练记忆，隔离开发资料不能证明模型从未见过题目。

历史报告区分共享上下文、逐题隔离和前置门控诊断，不能把这些不同协议的成绩当作 Skill 的单因素对照。历史提示、完整调用记录和题目正文仍保留在 `history/index.json` 指向的 LuoguBench 目录，本仓库不重复发布题目正文和完整调用轨迹。记录了输入、代码及结果指纹以便核对来源。历史重跑还依赖原宿主和模型可用性，不保证生成逐字相同。

操作命令、输入格式和新独立集协议见[使用说明](../../docs/cp-difficulty-luogu.md)。
