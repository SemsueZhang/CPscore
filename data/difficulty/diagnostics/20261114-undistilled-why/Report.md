# 无 Skill 基线为何领先：未蒸馏版本诊断

日期：2026-11-14。研究对象为同一个 GPT-6.1 Sol high，在基本评分提示与基本提示加冻结 Difficulty Skill 两种条件下的输出。正式 Skill 与空专家库没有改动。本文件是开发诊断，不是新增独立测试，也没有自动更新评分规则。

状态：五轮诊断已完成，包括统计复核、逐题理由复核、提示内容与反向词面检查、76 个新增评级的重复诊断、16 个评级的局部消融。正式 Skill 与专家库保持原样。

最可靠的结论是：原来少命中 3 题不足以证明无 Skill 具有稳定的能力优势。当前 Skill 增加了通用分析流程，却没有提供经验证的平台分档知识；它可能局部改变路线取舍和邻档定位。重复结果也显示出明显的同提示波动。下面分别列出支持这些判断的证据和不能推出的结论。

## 第一轮：先核对“更强”这一前提

原实验两组各 87/87 有效。无 Skill 基线命中 68 题，未蒸馏 Skill 命中 65 题。76 题输出同一档，另外 11 题全部只差一档，其中 Skill 降低 8 题、提高 3 题。没有观察到大量跨档崩溃。

仅基线命中 7 题，仅 Skill 命中 4 题。描述性的配对精确 McNemar 检验双侧 p=0.548828125。按题目重采样得到的 Accuracy 差值（Skill−基线）95% 百分位区间为 −11.49 至 +3.45 个百分点。它们不证明两种提示相等，也不估计重复生成的波动，题目家族独立性和总体随机抽样均未建立。

这些证据支持“这一次基线少错 3 题”，不支持“同一个模型加 Skill 后能力普遍变弱”。要解释的具体对象是任务表现和档位判断的变化。

复现统计：`python3 data/difficulty/diagnostics/20261114-undistilled-why/analyze_original.py`。数据见 `original-statistics.json`。

目前最清晰的现象是：不少题的算法事实基本相同，分歧发生在如何把这些事实映射到相邻平台档位。没有证据把全部 7 道新增错误归因于算法推理能力下降。

## 第三轮：检查 Skill 实际增加了什么

当前正式经验文件是空数组，评分规范只列八档数字与名称，没有经过验证的相邻档边界经验。新增内容主要是分析完整路线、独立发现、证明、知识、实现、替代路线等通用方法，以及版本、输出、工具和维护说明。基本提示原本也已经包含目标选手、满分解法、完整材料、八档名称和输出要求。

因此，这版 Skill 增加了流程要求，没有提供可核验的专家校准增量。要求模型再做一遍一般分析，不会自动产生洛谷分档所缺的经验。

更值得检验的假设是证据权重变化：一些输出在充分识别核心观察后，仍以发现后的算法或实现简洁来压低档位，或者把无需更高级算法作为邻档依据。这种变化有时纠正高估，有时造成低估，不能把它简单固化成“禁止降档”或“思维题一律抬档”的新规则。

为反驳过于方便的解释，又对原 87 题理由做了事后词面检查。预定的“简洁、简单、基础、模板、无需”等词组，两组总命中均为 94 次，分别出现在 65、64 条理由中；“独立、发现、非显然、证明、论证”等词组在基线 / Skill 中命中 124 / 163 次。理由平均长度为 111.4 / 114.8 字。这是粗糙的词面描述，不能读取真实权重或推理过程，但不支持“Skill 在全局上一味更强调简单、忽视思维”这个方便说法。它更像是促使模型提到了希望分析的因素，却没有可靠改善因素到平台档位的映射。计数与正则表达式见 `original-reason-lexical-check.json`。

下面几种常见解释也需要克制：

- **思考变少**：原实验 Skill 组推理 token 为 19,931，基线为 17,670，反而更多。更多 token 不保证思考质量，但当前计数不支持“因为没思考所以更差”。
- **格式或档位转换错误**：两组无无效输出，原生 1～8 直接计分，没有旧 0～7 的中间转换。这些执行错误不是已观察差异的解释。
- **上下文溢出**：输入平均从 21,234 增到 22,706 token，单次最大分别 38,071、39,312，没有记录到材料截断或输出无效。提示更长可能改变行为，但不能直接宣称上下文过长导致此次下降。
- **题目记忆**：公开旧题可能被识别，无 Skill 基线可能更直接使用学到的平台分布或题目记忆。当前没有证据证明原调用使用了答案记忆，也没有未见题测试来排除它，故保留为竞争解释。
- **包装性说明**：版本、工具、单题未知值等文字与本次评分关系较弱，但是否造成认知干扰尚未做消融。零格式错误不能证明这些文字完全无影响，也不能证明它们导致少命中 3 题。

OpenAI 的推理提示文档建议清楚直接地给任务、约束与输出，并提醒普通的逐步推理提示不一定有益。评测文档强调同输入的生成也可能变化。这些只是支持实验设计的一般指导，不能替代本次的因果证据。

## 第四轮：预先记录的有限重复诊断

为区分提示作用和重复波动，保留所有 11 道原分歧题，再按原预测档位从原稳定题中各选一个固定哈希最小的对照，共 19 题。选对照时不按真实标签或正确与否过滤。每种提示各追加两次独立调用，计划得到 76 个新增有效评级。

所有重复请求逐字等于原请求，模型与 high 推理参数相同，不提供旧评级、真实标签或其他题的历史。原本的 11 道分歧是事后选择，原差异会被选择放大，不能把 19 题的命中率包装成新的总体或独立成绩。

初次执行遇到连接层故障，原队列已停止，全部有效结果保留。短传输检查恢复后，只补没有有效结果的单元，最多两个并发请求。补跑仅改善错误记录，没有修改模型请求，且不替换任何已有效评级。失败与中止调用的实际计费无法从当前记录确认。

重复指标预先固定为：每题同提示三次是否稳定、新两次相对原调用的变化数量、两组新的档位移动方向、每一轮的正确数和误差。重复观测不能冒充互相独立的新题。全部 76 个单元通过审计后才生成描述性计分。

重复诊断已全部完成，76 个新增有效评级、76 个不同会话，与该子集的 38 个原始会话也无重合，共 114 个独立上下文。恢复阶段没有再次失败。结果采集脚本为 `collect_repeats.py`，计划见 `repeat-plan.json`，记录见 `repeat-results.json` 和 `repeat-cases.json`。

两种提示均有 7/19 题在三次调用中发生过档位变化。无 Skill 的 38 个新增评级中，10 个不同于自身的原评级，Skill 为 11/38。原来 11 道分歧题中，只有 P7114 在这三次调用中保持两组等级完全分离；其余 10 题至少出现过两组取值重叠。取值重叠不证明两个输出分布相同，19 题复测也不等于全 87 题重跑。

## 第五轮：只对唯一稳定案例做局部消融

选取唯一三次严格分离的 P7114，并加入预先固定的原预测第六档稳定对照 P2680。选择依据是输出稳定性，不按真实标签过滤。四种条件各调用两次，共 16 个评级：原基本提示、原完整 Skill、完整 Skill 删去三处替代路线选择指令、只保留原分析内容而移去工具/版本/输出包装。原两种条件的请求仍逐字等于原请求。

删除路线指令的确切文字、保留的分析片段、固定调用顺序和局限都在新请求执行前冻结。它不是新 Skill 候选评测，不向模型提供先前评级或目标档位。正式 Skill 文件保持原样，不根据两个案例选择发版方案。

这项实验只检验一个局部机制，不将两个案例的结果推广为“所有路线比较都不好”。分析内容条件同时改变了包装、结构与长度，不能单独识别“字数”的作用。16 个有效评级、16 个不同会话全部完成，无新增执行失败。

| 条件 | P7114 两次评级（真值 6） | P2680 对照两次评级（真值 5） |
| --- | --- | --- |
| 原基本提示 | 6、6 | 6、6 |
| 原完整 Skill | 5、6 | 6、6 |
| 完整 Skill 删去三处替代路线选择指令 | 6、6 | 6、6 |
| 只保留原分析内容，移去操作性包装 | 5、5 | 6、6 |

这与局部路线选择作用相容：原 Skill 理由倾向强调较简单的调和枚举已经可以满分，不必独立发现线性优化；删去路线选择指令后，理由更强调组合观察、复杂度和常数压力，并落在 6 档。仅去掉工具、版本等包装没有使该案例回到 6，故不能用“只是提示太长”解释它。

同时，完整 Skill 在同时段测试中也给出一次 6，打破了先前三次的恒定分离。单个目标、两次观测和一个指令束的删除，不足以证明唯一原因，更不足以解释全 87 题的差值。路线比较本身有合理性，不能为了这道题的标签直接删掉正式规则。

P2680 在四种条件下均为 6，仍与原生 5 档不符。删操作文字或删路线比较都没有补上这一平台分档缺口。它也反驳了“无 Skill 已经完全掌握平台尺度”的说法。

原始评级与理由见 `ablation-observations.jsonl`，汇总见 `ablation-results.json`，确切删除文本和操作边界见 `ablation-plan.json`、`ablation-variant-snapshots.json`。这些变体仅用于事后诊断，未作为正式 Skill 或经过验证的专家经验发布。

## 当前可成立的解释

最有证据支持的是“当前 Skill 尚无专家校准信息，而额外的通用分析要求可能改变了邻档边界取舍”。“它损伤了模型的算法能力”“越短越好”“必须把所有思维题抬高一档”都超出了证据。

在所选子集中，重复调用有时改变原本的领先方向，不能把原来全 87 题的 3 题优势全部解释成 Skill 损伤算法能力。这里没有重跑全 87 题，未估计全体题目上的稳定效应，也没有做能完全隔离长度、措辞与框架的多因素因果研究。

对下一步工作的启示是：专家经验应补充相邻洛谷档位的具体判断边界、条件与反例，而不只是再次列出完整路线、独立发现、证明和实现等一般因素。尤其应区分“知道一种较简单算法存在”和“目标选手独立发现并可靠完成它的困难”。这仍是待人工审核与独立评测验证的方向，不是本次已验证的新规则或准确率保证。

本次不修改正式 Skill，不从这两个案例抽出算法名到档位的对照表，也不将旧开发集重包装为独立测试。已完成的结论是对当前失利现象的有限解释和反例检查，未声称识别了模型内部唯一机制。

本次新增 92 个有效评分（76 个重复、16 个消融），另有一次不计成绩的合成题连接检查。初次重复运行记录了连接失败，停止了三个仍在运行的原队列，所有已有效评级原样保留；恢复后只补无有效结果的单元，没有因评级不符预期而重新选择输出。失败或中止请求的实际模型用量与账单不能完整确认。
