# 题目难度评定

根据题面、完整可通过解法、约束及必要实现评定难度。默认背景是未见本题或直接先例的个人选手，允许竞赛常用模板，独立完成全数据算法、证明和程序。团队、语言、模板或工具背景有约定时采用实际约定。

## 评定方法

1. 读取[三维与总档规范](references/rubric.md)，固定一条完整可行路线，核对真正影响难度的正确性、复杂度与实现条件。缺少完整路线时可补推导，仍不完整则仅给已有部分的初评和具体缺口。
2. 根据该路线分别评知识 K、思维 T、实现 I，各用 0～5 六档，引用必要知识、发现线索与最大跳跃、状态及边界作为依据。先固定这些判断，再查看外部难度标签。已知题目身份或 rating 时说明影响。
3. 结合整条路线与规范中的相邻档锚题，给出 0～7 的总档和必要的邻档区间。多条可通过路线分别完整评分，以总难度最低的实际可行路线为题目主评，并保留重要替代路线。不要跨路线拼接最低三维。
4. 按[平台适配](references/platforms.md)给出 CF 与 AtCoder Problems 的题目难度参照。已知原生标签时单列来源、日期与字段，和内容评定结果对照。平台换算只提供粗略参照，不能生成 K/T/I 真值。

## 交付

先给题名、总难度数字及洛谷档名，再给简表：

| 项目 | 结果及依据 |
| --- | --- |
| 评分路线与背景 | 全数据路线、复杂度、模板及语言条件 |
| 知识 K / 思维 T / 实现 I | 各自 0～5、档名及具体依据 |
| 总难度 | 0～7、洛谷档名，与相邻档的区别，必要时给邻档区间 |
| CF 参照 | 题目 rating 区间、适配版本，或已核实原生 rating |
| AT 参照 | AtCoder Problems 显示 difficulty 区间、适配版本，或已核实 raw / 显示值 |
| 判断把握与缺口 | 哪些依据充分，哪些因素可能改变评级 |

默认在对话输出 Markdown，用户要求保存时再写文件。区间是粗略等级参照，不是统计置信区间。题目难度与材料质量、新颖度、选手水平、预计分钟数分别判断。没有经验证的模型时，将总档写为“依据规范和锚题的评定”，不冒称训练模型预测或实测准确率。

数字转换可使用随包的 Python 3.8+ 标准库脚本 [platforms.py](scripts/platforms.py)。宿主没有 Python 时直接使用平台适配表，不要求安装运行时。

# 三维与总难度规范

版本：`cpscore-difficulty-v1`，2026-11-13。迁入 Auto-Insight 已有的三维定义，只把总难度改为洛谷对应的八档。三维仍为 0～5，不能将三维数字当作八档总难度数字。

## 三维各评什么

| 维度 | 评价对象 | 依据 |
| --- | --- | --- |
| K 知识门槛 | 独立解题前必须掌握的知识及理解深度 | 必要知识、适用条件、熟练程度。题内可推出的性质归 T，避免重复抬档。 |
| T 思维难度 | 已掌握所需知识后，从题面发现并证明整解的难度 | 自然尝试、可用线索、最大跳跃、观察依赖、证明障碍。事后讲解简短不表示容易发现。 |
| I 实现难度 | 已给算法与必要不变量后，完成可通过程序的难度 | 状态维护、结构耦合、更新顺序、边界、精度及调试。算法发现负担归 T。 |

| 数字 / ID / 档名 | K | T | I |
| --- | --- | --- | --- |
| 0 / light / 小学 | 基本语法、算术与直接模拟 | 处理方式基本由题面给出 | 状态和边界很少的直接逻辑 |
| 1 / easy / 初中 | 基础算法和常用方法的基本应用 | 少量常规观察或直接转化 | 少量状态与常见边界 |
| 2 / mid / 高中 | 理解并运用竞赛常用算法的性质 | 非平凡转化，或多个有线索的依赖观察 | 多阶段或多状态，需要明确不变量 |
| 3 / high / 本科 | 深入掌握高阶方法与关键性质 | 深层建模、较长推导或困难的全局论证 | 较强结构耦合，边界与调试负担明显 |
| 4 / xhigh / 硕士 | 专门方法或深入性质及其适用条件 | 多次困难突破，或难发现的核心转化和证明 | 多个复杂结构紧密配合，精细维护负担很重 |
| 5 / max / 博士 | 训练覆盖少、理解与熟练运用均极难的专门知识 | 极难的突破或推导，有具体可说明的发现障碍 | 高度耦合或精细维护，正确落实本身极难 |

学段名称是沿用的标签，不表示真实学历。算法名、论文出处、代码行数与新颖度不能直接定档。允许现成模板时，K 仍评价选用和理解所需的知识，I 按实际需要编写、衔接和调试的部分判断。

历史人工反馈仅确认五个轴：CF946B T=0、CF643B T=1、CF1619D T=1、P3373 K=2、CF39G I=3。没有同时确认其余轴或模型给出的理由，不将这五个数字推广为整库统一改档。其余历史机器草稿保留弱标签身份。

## 八档总难度

与[洛谷当前难度体系](https://help.luogu.com.cn/manual/luogu/problem/difficulty)及[用户指定讨论](https://www.luogu.com.cn/discuss/1312513)的八个类别对应。以下简述用于比较整条路线，算法名称只是例子。

| 总档 | 洛谷名称 | 整题比较重点 | 路线锚题 |
| --- | --- | --- | --- |
| 0 | 入门 | 基础程序逻辑 | [P1001 A+B](https://www.luogu.com.cn/problem/P1001)：直接读入、运算、输出 |
| 1 | 普及- | 基础方法的直接应用 | [P1873 砍树](https://www.luogu.com.cn/problem/P1873)：单调判定与二分边界 |
| 2 | 普及 | 基础方法中的建模和观察 | [P5019 铺设道路](https://www.luogu.com.cn/problem/P5019)：区间操作转相邻增量，下界与可达性 |
| 3 | 普及+/提高- | 常用结构与性质的灵活运用 | [P3373 线段树 2](https://www.luogu.com.cn/problem/P3373)：仿射懒标记复合与维护 |
| 4 | 提高 | 较深入的推导与算法配合 | [P2680 运输计划](https://www.luogu.com.cn/problem/P2680)：二分、树上路径约束与公共边判定 |
| 5 | 提高+/省选- | 多个关键结论形成整解 | [P7077 函数调用](https://www.luogu.com.cn/problem/P7077)：共享调用 DAG 的乘数与逆序贡献传播 |
| 6 | 省选/NOI- | 深层转化、构造及证明 | [P7115 移球游戏](https://www.luogu.com.cn/problem/P7115)：栈间分离构造、分治及操作数界 |
| 7 | NOI/NOI+/CTS | 极难的综合突破 | [P5659 树上的数](https://www.luogu.com.cn/problem/P5659)：交换删边转局部边序，支撑可延拓的逐位贪心 |

档位名称和锚题来源分类在 2026-11-13 核对。洛谷定义仍可能调整，复评明确采用的版本。P4502 的历史材料存在坐标与退化保证缺口，不用它作为已核实的实现锚题。洛谷“暂无评定”是未知，不属于上述八档。

## 如何形成总档

三维是整条解法的摘要。总档综合评价同一条路线中知识、发现、证明和实现的整体负担。比较关键障碍与相邻两档锚题，说明为什么更接近某档，避免只按算法名字判断。纯思维题可以 K、I 很低而总档很高，模板题也可能 K 高于其发现负担。

相同 K/T/I 可能压缩了不同的档内难度，允许根据路线的具体依据形成不同总档，并解释差别。不能仅用三维最大值、均值、固定权重或线性拉伸 `0～5 → 0～7` 决定总档。没有被验证的八档合成器时，不声称存在唯一的 216 格组合答案。

实质更简单的全数据路线会改变题目难度。对每条路线单独给三维和总档，核对其复杂度、实现资源及模板条件后选主评。部分分路线另列，错误做法和未证实可行的做法不参与“最低可行路线”的比较。

在缺口会改变档位时给主档与可能邻档，并指出需要补充的事实。把握来自路线理解、锚题比较与材料完整性，不将模型自报置信度解释成概率。若仅有部分分路线，不能把该路线的档位写成题目全数据难度。

## 研究版本边界

Auto-Insight 历史试验使用 67 条机器弱标签，其中 66 条用于首轮合成器试验。CF 六道留出题上，学习模型 MAE 398.9，最大维度基线 333.0。旧六档模型未被采纳，不能通过改输出名称成为已验证的八档模型。本技能采用规范、锚题与路线评定，未训练材料到三维的学生模型。

后续若引入学习合成器，保留 K/T/I 的维度身份和单调约束，目标为八档，按题族留出并与简单基线比较。仅改变目标档数不会增加三维的 216 种组合，但有序分类切点改为七个。正式使用依据独立评价，历史人工反馈、弱标签和测试题用途分别记录。

# 洛谷、CF 与 AtCoder 适配

版本：`cpscore-platforms-20261113-v1`。总档使用洛谷八档，CF 与 AT 分别从同题原生标签拟合，不把两站的同一数值视为等难。

## 默认换算表

区间左闭右开，最后一档无上界。CF 指**题目 rating**，AT 指 **AtCoder Problems 显示 difficulty**，两者均不是选手 rating。

| 总档 | 洛谷名称 | CF 题目 rating 参照 | AT 显示 difficulty 参照 |
| --- | --- | --- | --- |
| 0 | 入门 | [800, 1000)；更简单题可能低于 CF 评级下限 | [0, 300) |
| 1 | 普及- | [1000, 1300) | [300, 700) |
| 2 | 普及 | [1300, 1800) | [700, 1300) |
| 3 | 普及+/提高- | [1800, 2000) | [1300, 1700) |
| 4 | 提高 | [2000, 2500) | [1700, 2300) |
| 5 | 提高+/省选- | [2500, 2700) | [2300, 2500) |
| 6 | 省选/NOI- | [2700, 3000) | [2500, 2900) |
| 7 | NOI/NOI+/CTS | [3000, +∞) | [2900, +∞) |

这些是有版本的粗略换算档，区间宽度不表示相等的能力差。将总档反查为原生区间，只得到该换算器的分箱，**不表示该档所有题的原生值均落在此区间**。不要称为统计置信区间、真实难度范围或官方跨站对照表。

有内容评定时，以完整路线、三维依据和总档锚题比较形成主评，再列平台参照。已核实的原生标签单列，两者不一致时说明具体瓶颈和尺度差异，不能为了匹配 rating 改写三维。只有原生数字时可以换算总档，但标为“由原生标签换算”，K/T/I 保持未知。

## 字段与身份

- **洛谷**：八档名称依据[帮助文档](https://help.luogu.com.cn/manual/luogu/problem/difficulty)。2026-11-13 的[配置](https://www.luogu.com.cn/_lfe/config)中，原生 difficulty ID 1～8 依次对应本技能 0～7。原生 ID 0 是“暂无评定”，返回未知，绝不能转成入门或负数。使用名称时按表匹配，注意减号 `-` 与 `−` 的显示差别。
- **CF**：读取[官方 Problem 对象](https://codeforces.com/apiHelp/objects#Problem)的 `rating`。缺失、未定级是未知，不用题目分值、比赛题位或选手 rating 代替。评级下限附近不能细分所有基础题，低于 800 的参考描述不能冒充官方题目 rating。
- **AT**：读取[AtCoder Problems 社区模型](https://kenkoooo.com/atcoder/resources/problem-models.json)的 `difficulty`，按稳定 task ID 匹配。它不是 AtCoder 官方难度，也不是题目分值。ADT 重用题和 ABC/ARC 共享题按 task ID 去重。AHC 的优化分数不适用本表。缺失或非有限值返回未知，experimental 值注明不稳定，不作为可靠校准标签。

AtCoder Problems 的[前端转换](https://github.com/kenkoooo/AtCoderProblems/blob/main/atcoder-problems-frontend/src/utils/index.ts)为：

```text
display = round(raw)                          raw >= 400
display = round(400 * exp(raw / 400 - 1))      raw < 400
```

round 使用 JavaScript `Math.round` 对非负值的规则。raw 可以为负，例如 raw=0 的显示值是 147，raw=400 的显示值是 400。已经显示的 difficulty 不能再次转换。`slope` 属于另一项模型参数，可以为负或缺失，不能据它推断 `difficulty` 缺失。本次将 raw=-10000 的极端地板值单列排除，而非排除所有负 raw 值。

## 适配依据与表现

[同题快照](platform-anchors.json)保留原站 task ID、洛谷镜像、原生值、日期、响应指纹、选题与排除原因、development / holdout 用途。数据来自 CF 官方 API、AtCoder Problems 模型，以及洛谷同 task ID 的题目页和分类列表。只取难度元数据，没有读取 Auto-Insight 原洛谷十六道测试题的题面、题解或三维答案。

共保留 305 条记录，303 条可用：CF 149 条、AT 154 条。原小批对照均作为开发材料。补充时按各站洛谷八档扫描列表，取足够匹配题的最早页面，排除已有身份及无有效原生值的题，再按固定 task ID 哈希顺序选每档五道留出、十道开发。拆分在查看留出指标前固定。开发集 CF 109、AT 114，留出各 40、每档各 5。列表排序与分层选题有偏，未声称是各站总体的随机样本或近变体完全无泄漏的证明。

两站独立拟合七个严格递增切点，在 100 点网格上最小化总档绝对误差。平局优先靠近各边界的最优区间中心，再按切点字典序确定。切点仅用开发集拟合，未在留出结果上调参。模型和逐题结果见[适配参数](platform-calibration.json)。

| 站点 | 留出题数 | 总档平均绝对误差 | 完全命中 | 相差至多一档 | 最大跨档误差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| CF | 40 | 0.600 | 20/40 | 36/40 | 2 |
| AT | 40 | 0.350 | 27/40 | 39/40 | 2 |

结果只衡量**原生难度到洛谷档次的转换**。未验证题面到三维、三维到总档、全 skill 评级准确率，也不检验预训练未见的新 trick。使用时保留“粗略参照”身份，针对题型及路线的偏差说明原因。

## 随包数字工具

在技能目录中，用已有 Python 3.8+ 执行，无第三方包、API key 或联网要求：

```sh
python3 scripts/platforms.py --level 4
python3 scripts/platforms.py --cf 2200
python3 scripts/platforms.py --at-raw -197
python3 scripts/platforms.py --at-display 1528
python3 scripts/platforms.py --luogu-id 0
```

工具只转换传入数字，未自行查询原生标签或分析题目。输出含版本、来源尺度、观察范围外标记及每档开发样本数。实际报告还需说明所用题目、路线与来源。

离线复现拟合和留出指标：`python3 scripts/calibrate_platforms.py`。默认打印 JSON，需要文件时加 `--output /absolute/path/to/result.json`。冻结快照和旧指标不因重复执行而产生新的独立证据。
