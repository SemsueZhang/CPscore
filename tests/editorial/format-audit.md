# 多轮格式核查记录

日期：2026-11-14。目标是核查并修复格式引擎的漏检、误报、异常输入、位置计数和评分接入问题，不通过修改十篇原稿或关闭规则制造零发现。按用户后续要求，现行 v2.2 为脚本优先、审核 LLM 核验不能确定的部分、脚本统一合并计分，不设人工步骤。同类 1～2 处 Confirmed 为 Major、至少 3 处为 Fatal；剩余未确认项不能当成确定错误次数。

## 第一轮：正常写法与未验证范围

开始时基线：格式引擎 v2.1，118 项单元测试通过。对额外构造的源码进行实际扫描，复现如下缺陷，修复状态以测试和当前代码为准。

| 编号 | 已复现的缺陷 | 状态 |
| --- | --- | --- |
| A01 | 单独 CR 换行的行号错误，Unicode 行分隔符被 Python `splitlines` 当成 Markdown 新行，制造不存在的软换行 | 已修复，含 CLI 原换行及摘要验证 |
| A02 | 合法 Setext 标题被判缺句末标点 | 已修复，覆盖单行、多行及数学标题 |
| A03 | `中文_English_` 中不成立的强调被剥除，造成缺空格误报 | 已修复，按定界条件处理，字面用途未明时仅 Warning |
| A04 | `\verb|%|` 中的百分号被误当注释，后面的未知命令被漏掉 | 已修复，先保护 verb 再识别注释 |
| A05 | 白名单误含 `\lf`、`\loor`、`\dx` 等未验证命令，会直接通过 | 已修复，改为未验证命令 |
| A06 | 未知扩展容器、未闭合折叠容器和无对应开头的容器结束标记直接通过 | 已修复，配对或保留未验证信号，summary 可见文字参与检查 |
| A07 | 表格内转义的字面竖线被当成单元格分隔符，其旁边的多余空格漏检 | 已修复，区分转义竖线和分隔符 |
| A08 | 七个及以上井号的疑似标题没有任何未确认信号 | 已修复，保留标题意图 Warning |

原始探测使用的十篇快照沿用 [format-regression.md](format-regression.md) 的摘要。修改前检查器和结果临时保存在 `/tmp/cpscore-format-audit-20261114/`。

此外修复了路径解析失败会中断整批扫描的问题，以及源文保留标记字符被当成内部哑标记的问题。第一轮结束时 143 项测试包含 1,200 组固定种子生成输入，检查异常输入不中断、行列与源片段对应。生成输入不提供格式语义 Gold。

使用宿主已提供的 Marked 17.0.5（`gfm=false, breaks=false`）验证了 Setext 和强调定界的代表案例：`中文_English_`、`中文**$x$**` 均未形成强调，而 `中文**English**`、`中文 **$x$**` 形成强调。该工具只用于开发期对照，不增加脚本运行依赖，也不代表洛谷页面实测。

| A15 | `\frac{1}`、`\sqrt` 缺少必要参数仍通过 | 已修复，`TEX015` 校验简单必需参数、根号指标、环境参数与定界符；合法原子参数保留，复杂展开转 LLM |

较小探针中，纯 `h` 正文从 4,000 到 8,000 字符的旧耗时约从 0.041 秒增到 0.158 秒；修复后 8,000／16,000 字符约为 0.008／0.015 秒。公式探针修复段落缓存后，4,000／8,000 个公式约为 0.049／0.110 秒。这些是本机观察，不是跨机器性能承诺。

开发期对照使用 [KaTeX 支持表](https://katex.org/docs/support_table.html)及[语法示例](https://katex.org/docs/supported.html)，页面版本 v0.19.1。移出直接支持清单的名字包含 `mbox`、`lcm`、`infinity`、`percent`、`spacing`、`cline`、`multicolumn`、`cases`、`newenvironment` 等。名字核对不证明全部参数合法，也不代表洛谷当前配置。没有加入渲染库、安装、运行期联网或模型调用。

复核接口单元测试验证结构、来源绑定、去重与严格回退，不证明 LLM 理由的真实性。另有 250 组固定种子输入检查候选唯一、未确认裁定不改变原评分、合并不修改原始扫描。
