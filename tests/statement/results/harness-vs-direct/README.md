# CPScore 与无 CPScore 的对照

本实验回答：同一 Codex 宿主、同一 `gpt-6.1-sol`（`xhigh`）在题面审核任务上，加载 CPScore `cp-statement-review`，相较直接审题有什么增量。先前 `../final/` 的结果是两个 CPScore 版本之间的比较，不能回答这个问题。

CPScore 组复用 `5af3cda` 的 108 次主审核与 20 次候选复审。直接组使用同样的 56 个正式版本、12 版本各 5 次的重复审核及 4 个等价版本，共 108 次主审核；修复选择相同 20 个根因。第一轮与重复审核不重复计数。8 次技术 Smoke 来自开发家族，输入及设置完全一致时复用到正式组，不按得分选择。

直接组目录仅有 `material.md` 与 `request.txt`，不提供 Skill 或方法 Reference。它得到基本审核任务、与 CPScore 对齐的通用分级和去重约定，以及完全相同的 JSON 输出格式。这是一个有共同评分尺度的直接模型基线，没有复制规格重建、对抗性解释、边界检查或阅读路径流程。平台格式规范收益与语义、样例及文字问题检出收益分开统计。

每次直接调用通过 CLI 覆盖禁用八个 CPScore Skill 的名字；不修改用户配置。设置依据 [OpenAI Docs 的 Skill 配置说明](https://learn.chatgpt.com/docs/build-skills)和[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)，实际参数、载荷清单与访问行为以本轮命令和原生日志核对。双方保留 Codex 底座、只读工具权限、临时会话及认证方式；本实验不是完全移除宿主、直接调用裸 API 的比较。

## 完成结果

两组各有 108 次主审核完成，运行宿主均为 `codex-cli 0.167.0-alpha.4.1`。直接组另完成 19 次候选复审，1 个格式目标没有实际修订建议，记 unavailable，仍计入 20 个修复目标的分母。详见[完整报告](report.md)与[原始计数](report.json)。

| 指标 | CPScore | 直接审题 |
| --- | --- | --- |
| 语义、样例与文字根因检出 | 29/29 | 29/29 |
| 格式根因检出 | 1/1 | 0/1 |
| 冻结 Gold 等级准确率（已检出项） | 30/30 | 27/29 |
| 重复审核核心集合众数一致性 | 60/60 | 58/60 |
| 重复审核出现无依据扣分 | 0/60 | 2/60 |
| 有效修复（固定 20 个目标） | 19/20 | 17/20 |
| 排除格式目标后的有效修复 | 18/19 | 17/19 |

本轮观察到少量稳定性、规范执行与修复保持性收益，未观察到非格式根因检出率提升。两项修复差异中，一项是直接组没有格式修订建议，另一项是浮点案例 `st-011-mutant`：直接组首选混合绝对/相对误差，消除零除却放宽了原本明确的非零判定；CPScore 只补零坐标分支。该变化经独立有理数程序和父子规格对照确认。两组在 `st-025-base` 都额外改变了明确的道路模型。

“有效修复”沿用预登记口径：消除目标根因、无新增规格错误，且不改变目标缺陷之外已明确的规则。两组根因消除分别为 20/20、19/20，确认新增规格错误均为 0。两组各有 5 个输入域、模型或预算变化，另列在报告中，不能把有效修复等同于完整保留原设计。

直接组两次无依据扣分都把单反斜杠误读为双反斜杠：[st-017 第四轮字符核对](direct-017-r4-escape-audit.json)、[st-009 第五轮字符核对](direct-009-r5-escape-audit.json)保留了源文与引文证据。等级差异的两个案例均实际检出了缺陷；直接组未获 CPScore 完整细化判据，因此等级一致性收益不能视为数学能力提升。

按 CPScore 的明确输入说明要求，维护者另确认 `st-029-base`、`st-038-base` 的字段含义缺项，只有 CPScore 组报告，未写回冻结 Gold。但 CPScore 将前者判为 Minor，低于其适用的 Major 标准，故这两项的等级准确率只有 1/2；不能用冻结 Gold 的 30/30 掩盖这一缺口。这些属于规范执行差异，未经人类专家确认。

主表检测指标只配对共同已裁定的 53/56 个正式题面。除两个未确认阅读 Gold 外，直接组 `st-019-base` 的固定 C++ 接口缺项主张仍待核验：题面提供抽象函数协议，未指定固定 ABI，尚不能确认其是否必需。该项不记误报、不用于宣称 CPScore 收益；正确题误报率两组均为 0/23。

| 108 次主审核的资源记录 | CPScore | 直接审题 |
| --- | --- | --- |
| 输入 tokens（含缓存） | 9,135,032 | 5,936,099 |
| 其中缓存输入 tokens | 7,584,000 | 5,239,680 |
| 输出 tokens | 297,791 | 185,748 |
| 调用耗时中位数 | 80.30 秒 | 60.78 秒 |

输入约为直接组的 1.54 倍，输出约为 1.60 倍。小样本及历史运行条件不支持显著或普遍提升的结论。

## 冻结与存档

- [protocol.json](protocol.json)：比较问题、分组、主要指标与修复政策。
- [direct-freeze.json](direct-freeze.json)：Smoke 之后、正式直接组之前固定的提示、程序与数据协议哈希。
- [direct-request.txt](direct-request.txt)：直接组的完整、无案例标签请求。
- `direct-smoke/`：8 次真实调用已完成；6 道正确题未列扣分项，两个顺序/方向缺失案例报告 Fatal。仅作为技术检查，不推出效果结论。
- `direct-development/`、`direct-holdout/`：61 次开发、47 次留出调用均完成；前者含 8 次 Smoke 精确复用，提示未据开发分数改写。
- `direct-final/`：合并 108 次不同主审核会话，107 份裁定闭合，1 份接口疑点未决。
- `direct-repairs/`：19 份来自实际建议的首选候选，均有差异、论证、实际执行的有限核验及最终 assessment；另 1 份无建议记录。
- `direct-repair-reviews/`：19 次新会话复审完成，不因复审结果改选下一套建议。
- [archive-audit.json](archive-audit.json)：127 个直接组会话和复用的 128 个 CPScore 会话，共 255 个不同原生会话；127 个直接组二文件载荷及重新执行的 19 份修订程序通过离线核对。此审计与旧版评测共享会话，不叠加为样本数。

原题、Gold 和两个 CPScore 快照均沿用原冻结。未知问题先独立核验，不能因 Gold 未列就当误报；两个阅读质量 Gold 继续保持 `needs_review`。C 取报告顺序中第一套连贯建议，配套改动一起应用；实际可选建议若明确对应目标，也属于可用建议。没有实际建议时记 unavailable，不从 Gold 制造理想补丁，20 个目标仍全部留在分母中。条件方案由合成题作者（维护者模型）选择，非人类作者确认。

## 运行入口

```sh
python3 tests/statement/scripts/evaluate.py plan --direct --suite campaign --split development --output NEW_PLAN.json
python3 tests/statement/scripts/evaluate.py run --plan NEW_PLAN.json --output NEW_EMPTY_DIRECTORY --workers 4
python3 tests/statement/scripts/compare_harness.py
python3 tests/statement/scripts/compare_harness.py --audit
```

上述 `plan`、`run` 用于新实验，不能覆盖已冻结存档。同一条件的开发与留出结果可用原有 `merge` 命令合并为新目录；原生会话、原始回答和裁定保留。`compare_harness.py` 读取保存结果，不调用模型，按共同已裁定案例比较，列出覆盖缺口、类型表现、核心集合稳定性、修复及资源开销。`--audit` 另核对载荷、哈希、建议来源、独立会话身份和实际访问命令，并重新执行修订程序；该检查不是操作系统级读取屏障，也不证明任意自然语言正确。

harness 为历史真实结果，直接组随后运行。请求的模型别名相同，但后端权重版本未独立锁定，时间负载也不同；耗时只作描述。报告 provider 返回的输入、缓存输入与输出 tokens，不换算为账单价格。Gold、语义裁定和证明均由维护者模型完成，未经人类专家确认，生成者与被测模型未建立独立性。合成样本的确认子集可能存在天花板效应；真实题面的复杂语义、阅读体验及更广泛修复收益仍需独立复测。本轮仅覆盖冻结版本的题面审核，不外推其他七个 Skills；最新工作区 Skill 未测。
