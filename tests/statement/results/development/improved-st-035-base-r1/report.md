**f1 · [Fatal −10] 未规定同时发生的收入能否用于当天支付**

原文位置：`material.md` 第 3 行。

> 每天收到一笔收入并尝试支付一笔支出，两个事件发生在同一时刻。

“同一时刻”没有确定支付判定所用的余额。首次读到“如果尝试支付时余额不足”时，读者无法判断当天收入是否已经计入可用余额；后续输入、输出和样例也未排除其中一种解释。

最小合法区分实例：

```text
1 0
1 1
```

| 合理解释 | 当天过程 | 应输出 |
| --- | --- | --- |
| 当天收入可用于支付 | 可用余额为 1，支付成功，剩余 0 | `0 0` |
| 按收入到账前的余额判断支付 | 余额为 0，支付失败；收入到账后余额为 1 | `1 1` |

两种解释产生不同的失败次数和最终余额，影响输入—输出关系，属于已确认的规格歧义。

**局部修订：以下方案需作者选择其一。**

- 若当天收入可以用于支付，将上述原句替换为：“每天先收到一笔收入，收入到账后再尝试支付一笔支出。”
- 若当天收入不能用于支付，将上述原句替换为：“每天先尝试支付一笔支出，再收到当天的一笔收入。”

**修订复核：**两种方案均明确了顺序，并分别使区分实例的答案确定为 `0 0`、`1 1`；均与现有正式样例相容，不改变输入范围。建议尚未应用。

**其余核验结果**

正式样例合法：初始余额 3 已足够支付 1，两种解释下均无失败，最终余额均为 \(3+2-1=4\)，因此样例正确但不能消除上述歧义。

输入类型、数据行数、变量范围和输出字段顺序可确定；零金额、余额恰好够付没有发现独立缺陷。最终余额可能超过 32 位有符号整数范围，属于实现时的整数容量选择，不构成题面缺陷。适用的中文标点、数学表达及数据范围展示未发现独立违规。
