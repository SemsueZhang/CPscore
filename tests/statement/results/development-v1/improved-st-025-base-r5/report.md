**f1．[Fatal −10] 道路方向没有输入表示，最短通行代价无法确定**

原文位置：[material.md:3](/tmp/cp-statement-83wr_w9a/material.md:3)、[material.md:7](/tmp/cp-statement-83wr_w9a/material.md:7)。

> 道路可能单向通行，也可能双向通行。
>
> 第一行输入四个整数 $n,m,s,t$。随后 $m$ 行，每行输入三个整数 $u,v,w$。

题面允许两种道路，但没有字段或规则说明每条道路属于哪一种；单向道路的方向也没有明确约定。这影响输入与答案的对应关系，不能靠样例补全。

取达到最小城市数、最小道路数的输入：

```text
3 3 1 3
1 2 1
2 3 1
3 1 1
```

即使先统一约定单向道路沿 $u\to v$ 通行，仍有两种符合正文的道路配置：

| 配置 | 三条道路的实际方向 | 从 1 到 3 的最短代价 |
| --- | --- | --- |
| A | $1\leftrightarrow2$、$2\to3$、$3\to1$ | 2 |
| B | $1\to2$、$2\to3$、$3\leftrightarrow1$ | 1 |

两种配置都包含有向环 $1\to2\to3\to1$，均满足任意两个城市互相可达，也都同时包含单向和双向道路。因此，连通性保证不能消除分歧。上述距离已独立推算并用小程序复核。

现有正式样例在这两种配置下答案均为 `1`，样例本身未发现实质错误，但不能据此判断普遍规则。

这违反了规格 Reference 中输入含义应可确定、正文应独立说明任务的要求。由于同一份输入对应不同答案，按评分协议判为 Fatal；相关阅读障碍不重复扣分。

**局部修订：以下三种方案需作者择一，不能同时采用。**

- **若全部为单向道路**，将“道路可能单向通行，也可能双向通行。”替换为：

  > 每条道路均为单向道路，输入 $u,v,w$ 表示可从城市 $u$ 通行到城市 $v$，通行代价为 $w$。

- **若全部为双向道路**，将同一句替换为：

  > 每条道路均为双向道路，输入 $u,v,w$ 表示城市 $u$ 与城市 $v$ 之间可以双向通行，两个方向的通行代价均为 $w$。

- **若保留混合道路**，保留正文，将输入格式中的“随后 $m$ 行，每行输入三个整数 $u,v,w$。”替换为：

  > 随后 $m$ 行，每行输入四个整数 $u,v,w,d$，其中 $d\in\{0,1\}$。该行表示一条道路：$d=0$ 时仅允许从城市 $u$ 到城市 $v$，通行代价为 $w$；$d=1$ 时允许在城市 $u$ 与城市 $v$ 之间双向通行，两个方向的通行代价均为 $w$。

  同时将样例输入改为：

  ```text
  3 3 1 2
  1 2 1 0
  2 3 1 0
  3 1 1 0
  ```

修订复核：前两种方案分别固定道路类型，原样例输出仍为 `1`；第三种方案由新增字段确定方向，修改后的样例满足互相可达保证，输出仍为 `1`。三种方案均能消除已确认的歧义，但会明确原文尚未确定的输入模型，故均为条件性建议，尚未应用。
