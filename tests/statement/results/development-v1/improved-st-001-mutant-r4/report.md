## f1 · [Fatal −10] 处理顺序未提供，无法从输入确定答案

**原文位置：**[material.md 第 3 行](/tmp/cp-statement-9fb4k05d/material.md:3)。

> 管理员会在处理前私下固定 $m$ 份预约的处理顺序，选手不能改变该顺序，输入不提供这一顺序，输出编号仍采用输入编号。

**核验依据：**固定顺序仍会影响第一份失败预约的输入编号，但输入没有提供确定该顺序的信息。以下是满足全部约束的最小区分实例：

```text
1 2
0
1 1 1
1 1 1
```

- 管理员固定按预约 $1,2$ 处理：预约 $1$ 立即失败，答案为 $1$。
- 管理员固定按预约 $2,1$ 处理：预约 $2$ 立即失败，答案为 $2$。

两种情况均符合原文，输入完全相同，要求输出却不同。正文也没有约定可以任选一种可能答案，因此无法据此建立可判定的输入—输出关系。

**正式样例复核：**独立枚举全部六种处理顺序，结果如下：

| 处理顺序 | 第一份失败预约的输入编号 |
| --- | --- |
| $1,2,3$ | $2$ |
| $1,3,2$ | $2$ |
| $2,1,3$ | $1$ |
| $2,3,1$ | $3$ |
| $3,1,2$ | $2$ |
| $3,2,1$ | $2$ |

样例输出 $2$ 在部分顺序下成立，但无法由样例输入确定。这与正文的信息缺失属于同一根因，不另行扣分。

**实际影响：**选手即使完全正确地理解预约扣减规则，也无法对全部合法输入计算指定答案。

**局部修订：**需要作者选择处理顺序的规则。

若改为按输入顺序处理，可将上述原句替换为：

> 这 $m$ 份预约按输入顺序依次处理，输出编号采用输入编号。

**复核结果：**此方案消除了未提供的顺序参数；区分实例的答案确定为 $2$，正式样例输出仍为 $2$。它改变了原文明确规定的处理方式，须由作者确认采用。

若保留管理员任意指定的顺序，则须在输入中提供处理顺序排列，并同步修改输入格式和样例。该方案需形成配套文本后再复核。
