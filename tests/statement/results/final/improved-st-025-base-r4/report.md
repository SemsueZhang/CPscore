**f1 · [Fatal −10] 输入无法确定道路方向**

位置：`material.md` 第 3、7 行。

> 道路可能单向通行，也可能双向通行。

> 第一行输入四个整数 $n,m,s,t$。随后 $m$ 行，每行输入三个整数 $u,v,w$。

输入没有方向标记，也未给出确定道路方向的规则。“任意两个城市都可以互相到达”的保证不足以消除歧义。

取满足全部数值约束的最小规模实例：

```text
3 3 1 3
1 2 1
2 3 1
3 1 1
```

两种道路配置均符合正文及互达保证：

| 配置 | 道路方向 | 从 1 到 3 的最短代价 |
| --- | --- | --- |
| A | $1\to2,\ 2\to3,\ 3\to1$ | 2 |
| B | $1\to2,\ 2\to3,\ 3\leftrightarrow1$ | 1 |

因此，相同输入可能对应不同答案，无法确定接受条件。正式样例在这两种配置下均输出 `1`，不能帮助消歧。

**局部修订需作者选择以下方案之一。**

- **方案 A：若所有道路均为单向道路**，将“道路可能单向通行，也可能双向通行。”替换为：

  > 每条道路均为单向道路；输入中的 $u,v,w$ 表示一条从城市 $u$ 通往城市 $v$、通行代价为 $w$ 的道路。

- **方案 B：若保留单向、双向道路混合的设定**，将输入格式段落替换为：

  > 第一行输入四个整数 $n,m,s,t$。随后 $m$ 行，每行输入四个整数 $u,v,w,d$，表示一条连接城市 $u$ 与城市 $v$、通行代价为 $w$ 的道路。当 $d=0$ 时，道路仅允许从城市 $u$ 通往城市 $v$；当 $d=1$ 时，道路允许双向通行。

  同时在数据范围末尾补充 $d\in\{0,1\}$，并将样例输入改为：

  ```text
  3 3 1 2
  1 2 1 0
  2 3 1 0
  3 1 1 0
  ```

**修订复核：**方案 A 下，区分实例的答案确定为 `2`，原样例答案仍为 `1`。方案 B 下，两种道路配置具有不同的方向标记，答案分别确定；修改后的样例答案仍为 `1`。以上均为条件性建议，未应用到原文件。
