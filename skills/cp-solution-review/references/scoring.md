# std 分级与评分

以给定题解、std 和随附说明为整体，评价全范围实现正确性、资源要求及参考标程的表达质量。

## 缺陷等级

### Fatal −10

std 无法正确完成约定任务，须有合法反例、有效反驳、目标条件下的编译运行失败或充分的资源违例依据：

- 算法、转移、计数、初始化或多测状态错误，产生错误答案。
- 合法输入触发溢出、越界、未定义行为、递归错误或不终止，使任务失败。
- 最终源码无法编译、链接、完成实现或按目标协议读写。
- 部分分冒充满分，擅用规模假设，或最坏时间、空间、栈深超限。以原约定规格核验，不能按代码需要缩小范围。

### Major −2

实现仍能正确完成任务，但缺少理解核心实现所必需的信息，或存在重要方案、资源说明及验证交付问题：

| 问题 | 判据 |
| --- | --- |
| 核心记号与状态失去对应 | 核心量改名、复用或改变含义，代码与说明均无映射，需重新建立状态语义。 |
| 关键依赖缺失 | 压缩维度、清空时机、新旧值或更新顺序未说明，需重建核心不变量。 |
| 阶段与接口不清 | 关键输入输出、状态有效期、区间约定、归一化前提或副作用缺失，无法连接主要步骤。 |
| 核心说明错误 | 状态、转移、端点或阶段的说明与正确代码矛盾，误导核心理解。 |
| 复杂表达遮蔽逻辑 | 宏、副作用、无关分支或多层透传封装使关键转移、顺序或共享状态难以定位，需重组核心步骤。 |
| 方案或代价说明不符 | 未经约定换用题解无法解释的算法，或严重误述实际复杂度、内存峰值，但尚未构成资源违例。 |
| 验证或交付依据失实 | 用另一份源码、旧约束或部分分的验证支持当前交付，或缺少已约定的关键说明，无法核对标准方案。 |

### Minor −1

核心对应仍清楚，但存在具体局部阅读或核验障碍：未说明的局部记号、大小写变化，辅助量或接口说明疏漏，局部错误注释，公式堆叠或变量复用，干扰主线的遗留分支、模板，以及已约定的非关键交付说明遗漏。

## 判级边界

- 按答案、执行或理解影响定级。更新顺序导致错误答案为 Fatal，正确更新缺少核心依赖解释为 Major，非关键注释错误为 Minor。修复行数不决定级别。
- 不按封装方式、代码或注释数量、个人风格、无阅读影响的未使用头文件或存在更快正确算法扣分。独立对照表、固定格式、哈希及未约定的验证附件也不是必需品。
- 题解证明缺漏记录其来源与影响。std 实际错误按 Fatal，std 正确则按其自身对应性与表达评分，不移用题解的证明扣分。

## 计分与完成状态

`评分 = 10 − 10×Fatal数 − 2×Major数 − Minor数`，允许负分。

只扣已确认的独立根因，同一错误的答案、执行及理解后果取最高级别扣一次。疑点不扣分。

完成题解对应、表达、正确性与复杂度核验后，9～10分为“优秀，具备推荐资格”，6～8分为“尚可，值得打磨”，5分及以下为“不合格，存在重大问题”。缺题解、版本不对应、关键解释未核验或有未决正确性疑点时具体注明，6～10分首行写“暂定评分x/10，审核未完成，档次待定”。已确认分数≤5可判不合格并保留未完成范围。无确认缺陷可给10分。
