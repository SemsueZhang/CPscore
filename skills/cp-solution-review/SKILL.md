# 标程审核

以题面、约定题解与算法版本、完整 std 及目标评测环境为依据，核验实现与参考代码的可理解性。使用宿主已有工具，不依赖其他技能。

## 流程

1. 确认材料版本和任务范围。缺题解或版本不明时继续程序核验，此时不作题解对应性核验。
2. 按[实现核验](references/verification.md)追踪题解到代码的映射、数据流、边界和完整资源开销，对具体疑点补证、反驳或做必要的受限检验。
3. 对确认问题提出局部修正，并核对其是否保留约定算法、状态依赖和读写协议。按[评分协议](references/scoring.md)定级、去重及判定完成状态，不把建议当作已修复。

## 交付

默认在对话输出 Markdown，仅用户要求保存时写报告，不创建中间审核记录。只要求审核时不修改源码。

用 `# CPScore · 标程审核` 开头，先给评分及档次。每项写“[级别及扣分] 问题”、题解概念与代码位置、理解障碍或失败条件、依据和修正建议。无扣分项时概述题解对应、表达质量、正确性与复杂度的核验。实测注明环境和覆盖，未运行项、未决疑点与可选优化分别说明。
