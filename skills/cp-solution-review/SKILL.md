# 标程审核

读取题面、给定题解、完整 std、随附说明、约定的算法版本和目标评测环境。按[评分协议](references/scoring.md)检查实现能否正确完成任务，以及已读题解的读者能否理解代码。题解缺失或版本不明时，保留程序核验结果，标明题解对应性未完成。

## 核验

- **题解对应**：核对核心记号、状态、公式、阶段与指定方案，解释滚动数组、压缩、下标变换及等价改写的映射。
- **状态与数据流**：检查初始化、不变量、边界、新旧值和更新顺序，沿输入、预处理、计算、输出核对阶段衔接及接口的端点、前提、返回值和副作用。
- **表达质量**：检查注释、公式、控制流和封装能否支持读者追踪题解。区分材料已说明的对应关系与审查者自行补出的解释。
- **正确性与资源**：核验转移、覆盖、终止、中间运算、下标、容量、多测、递归、精度及读写协议，分析完整范围内的最坏时间、空间和内存峰值。
- **交付依据**：核对已声明的编译、样例及验证记录是否适用于当前源码和规格，区分证明、有限测试和上游声明。

以数学分析和逐项代码核对为主。对未决疑点构造合法小反例、有效反驳或必要的资源测量，分别核实输入、正确答案和程序行为。按需使用宿主编译器或正式评测环境，在合适隔离及资源限制下执行，取得可解释结果后结束该项检验。无执行条件时继续静态分析，工具失败不证明程序错误，有限测试不证明全范围正确。

## 交付

默认在对话输出 Markdown，仅用户要求保存时写报告，不创建中间审核记录。仅要求审核时交付发现及依据。

用 `# CPScore · 标程审核` 开头，先给评分及档次。每项写“[级别及扣分] 问题”、题解概念与代码位置、理解障碍或失败条件、依据和修正建议。无扣分项时概述题解对应、表达质量、正确性与复杂度的核验。实测注明环境和覆盖，未运行的检查如实说明。
