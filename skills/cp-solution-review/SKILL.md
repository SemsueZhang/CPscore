# 标程审核

依据题面、约定题解与算法版本、完整 std 和目标评测环境核验实现及表达。使用宿主工具，可独立安装。

算法知识、洛谷标签和知识门槛统一查询 `CPSCORE_CATALOG`（仓库默认 `resources/algorithm-catalog/`）中的 `catalog.json`；可用 `catalog.py search/get/tag/levels`，无 Python 时读同一 JSON。按 `luogu_tags.relation` 区分同义、较宽与上下文。`knowledge_level` 是知识参考，`problem_difficulty` 是非代表性标签样本，均不直接决定整题难度或选手掌握度。目录缺失时保留文字名、报告依赖缺失，不编造 ID／难度，不复制目录数据。

## 流程

1. 固定材料版本与范围；缺题解或版本不明时继续程序核验，题解对应性标为未核验。
2. 按[实现核验](references/verification.md)检查题解映射、数据流、边界及完整资源开销，对具体疑点补证或作受限检验。
3. 按[评分协议](references/rubric.md)定级、去重、说明完成状态，提出保留约定算法、状态依赖与读写协议的局部修改；建议不算已修复。

## 交付

默认对话输出 Markdown，仅要求保存时写文件，不另建中间审核记录；只审核时不改源码。

以 `# CPScore · 标程审核` 开头，先给评分与档次。缺陷列级别、扣分、题解概念与代码位置、失败条件／理解障碍、依据及改法。无缺陷时概述对应、表达、正确性和复杂度的依据。实测注明环境与覆盖，未运行、未决及可选优化分开说明。
