# 规格核验

## 形式化规格重建（Specification Reconstruction）

仅凭题面在内部建立合法输入域 $D$ 及合法输入—输出关系 $R(x,y)$：输入对象、类型与取值范围，初始状态，操作前提及执行顺序，计算、判定、优化或构造目标，以及合法输出、特殊情况和必要保证。对每个 $x\in D$，任务与接受条件应明确，按协议有可接受的输出或交互行为。

构造题、多解题允许多个合法 $y$，不要求答案唯一。无解须有输出约定或有解保证。优化题区分目标值与方案的要求。浮点题核对误差及接受条件，交互题核对询问、回复、限制、结束和异常协议，不能套用静态唯一输出模型。

追踪每条必要规则能否从题面定位，检查定义、量词、等价关系、区间端点、下标和数值类型是否自洽。领域惯例可解释常规符号，不能补上题目特有规则。由数学定义直接推出的性质无需逐条重述，输入域已排除的情形也不要求增加说明。范围缺失时记录所缺条件，不能按程序需要补约束，或自行认定某极值输入合法。

## 对抗性语义解释（Adversarial Interpretation）

对具体可疑表述尝试两个符合原文和领域惯例的合理解释，不为制造错误曲解通行术语。先检查全文上下文能否排除一种解释，再寻找尽可能小的合法输入，比较两种解释的操作过程和接受结果。构造题比较合法输出集合，而非仅比较两个不同但都正确的输出。

实例必须满足全部约束和保证。过程差异若不影响目标或判定，不能据此认定实质规格歧义。可用可靠数学推导或极小程序验证分歧，程序结果须说明所实现的两个模型与覆盖，不能用枚举未见差异证明一般等价。

据证据区分四类：已确认且影响任务或接受关系的歧义、语义可确定但增加阅读负担的问题、尚未裁定的具体疑点、可由上下文或惯例正常理解的省略。发现冲突后继续尝试上下文消歧，不以“能猜到作者想法”结束核验。

## 约束驱动边界分析（Constraint-driven Boundary Analysis）

从当前对象和操作选边界，先问“约束是否允许、哪个定义或步骤可能失效”，再构造输入。下表是候选方向，不要求逐题全做。

| 对象或操作 | 有关时深入的边界 |
| --- | --- |
| 序列与字符串 | 最小长度、空区间、端点、重复、零值，子串、子序列的连续性及顺序约定，空对象是否参与统计。 |
| 图与树 | 有向性、自环、重边、连通性、孤立点及特殊结构。树的根是否影响任务，单点、链或星形是否使定义失效。 |
| 构造与计数 | 无解、多解、等价关系、“本质不同”的口径、合法性保证与输出判定是否一致。 |
| 数值 | 实际允许的负数、零、极值，运算是否有定义，结果范围、取模与精度。实现中的溢出不自动等于题面缺陷。 |
| 状态操作 | 初始条件、顺序、重复操作、同时更新与顺次更新、终止或失败后行为。 |
| 多组测试与子任务 | 测试数、每组边界、总规模约束、输入行数、组依赖及分值能否唯一解析。 |

只追查可能影响题意或答案的情形，不替题目增加无关限制。正式样例逐个核对输入合法性、输出是否被接受及解释是否符合规则，优先独立推算或用独立小模型验证。多解题不要求与自算输出相同。复杂样例未能独立验完时明确范围，不以 std 一致宣称样例已经验证。

## 题面内容要求

以下为本协议直接执行的要求，与上述规格重建和边界方法一起核验。

| 项目 | 要求 |
| --- | --- |
| 任务说明 | 正文独立说明对象、规则和目标，不能让选手依靠样例猜出普遍规则。背景应帮助理解，不得用无关叙事掩盖必要条件，必要时补形式化说明。 |
| 概念定义 | 使用子串、子序列时说明连续性，统计全部子串或子序列时交代空对象是否参与。使用“本质不同”等等价概念时给出判定口径。相同对象的名称与变量大小写保持一致。 |
| 输入结构 | 写清数据类型、每行或每段的数量及含义。多组测试写清组数、每组结构及适用的总规模约束，不能让类型、行数或组界限依赖样例推测。 |
| 数据范围 | 说明必要输入量的上下界、字符串字符集和实数输入的小数位数，范围应与类型一致。例如不能同时称“正整数”又允许零。原则上应覆盖全部测试数据，子任务继承已说明的条件时可省去重复范围。 |
| 输出与判定 | 写清输出对象、格式、无解情形及接受条件。多解或允许浮点误差时说明特殊判题及接受口径，不能要求输出固定样例答案来代替判定定义。 |
| 取模 | 需要取模时，在任务描述和输出格式两处写清取模要求。模数和计算对象必须确定，交叉检查两处是否一致。 |
| 部分分 | 说明各部分的条件、分值及依赖关系。百分比表述必须能区分累计覆盖与另外一部分，不能让读者自行决定测试点属于哪组。捆绑计分应明确声明。 |
| 多语言 | 每个版本都应完整、独立地定义任务，不只提供形式化摘要。翻译不得增删影响任务的规则或夹入与翻译无关的内容，术语和约束须与原文一致。 |
| 时空限制 | 原则上至少留出参考程序最坏情况资源用量的 1.5 倍，不应明显过紧或无依据地放宽。检查环境、计量口径、最坏情况和合理例外，不能用普通样例的一次运行证明裕量充足。 |

明确要求、建议和原则性例外分别判断。上述内容中的排版与展示方式按阅读与修订协议检查，不能把算法洞察当作题面必须直接告诉选手的性质。

## 交叉材料

交叉材料用于定位冲突及其根因：题解可能揭示缺失规则，生成器只覆盖更小输入域不构成题面保证，判定器也可能错误。保持独立阅读得到的疑点，分别指出哪份材料与哪条规则冲突。

有 std、资源实测或翻译原文时才展开相应对照，区分资源裕量不足与已证实超限。未给这些材料不推定违规，具体记录未核验范围。
