# 题面审核

先只凭完整题面重建对象、初始状态、合法操作、执行顺序和目标，再用题解、程序或生成器交叉核对，不用隐藏的出题意图补齐规格。审核前读取[评分协议](references/scoring.md)和[洛谷规范核对表](references/luogu-standard.md)，按[易读性检查](references/readability.md)评价阅读成本。用户指定其他平台规范时说明适用差异，中文排版条款按题面语言适用。

## 核验

- 核对定义、量词、下标、顺序、重复、区间端点与数值范围，确认输入唯一确定任务，所有合法输入都有规定的输出。
- 检查输出格式及判定协议，尤其是交互、任意解、浮点误差和特殊判题。
- 检查实际允许的最小规模、空集、零值、极端数值、多测和无解情形，独立推算正式样例及解释。
- 逐项核对适用的排版、输入输出、数据范围、部分分和多语言要求。明确格式违规至少为 Major，严重妨碍核心题意或判定理解的可为 Fatal。区分明确要求、建议及原则性条款，按评分协议判断是否扣分。
- 检查语言、背景映射、规则组织、首次阅读体验、样例解释与材料可用性，定位具体误读或回读负担。
- 有参考程序、资源实测或翻译原文时，核对时空裕量及译文完整性。未提供这些材料时说明相应项目未核验，不据此推定违规。

用语义分析、数学推导或必要的极小检验裁定问题。领域惯例可解释常规符号，不能替代题目特有规则。材料不足时先完成可核验部分，列明缺失条件，不编造约束或把算法洞察当作题意补全。

## 交付

默认在对话输出 Markdown，仅用户要求保存时写报告，不创建审核台账或修改题面。

用 `# CPScore · 题面审核` 开头，先给评分及档次。每项写“[级别及扣分] 问题”、原文位置、依据、影响和修改建议。规范问题标明对应条款及适用条件，阅读问题说明具体理解负担并给局部改写。无扣分项时概述规格、规范与易读性的关键核验，不输出空清单。未扣分的建议与问题分开，按需使用宿主工具，如实说明具体未完成项。
