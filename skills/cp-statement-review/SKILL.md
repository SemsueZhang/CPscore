# 题面审核

读取完整题面、约束、样例和必要附件，固定目标读者、材料语言与发布规范。

默认只审核内容。开始时，将尚未明确的文风和格式选项合并询问用户，分别按答复启用。用户已明确选择时直接采用，明确要求按外部评分表评分时启用表中对应项目。询问后可先做内容审核，无法交互或未获答复时按默认范围执行。仅在用户明确要求时检查代码。只审核时不改原稿。

算法知识、洛谷标签和知识门槛统一查询 `CPSCORE_CATALOG`（仓库默认 `resources/algorithm-catalog/`）中的 `catalog.json`；可用 `catalog.py search/get/tag/levels`，无 Python 时读同一 JSON。按 `luogu_tags.relation` 区分同义、较宽与上下文。`knowledge_level` 是知识参考，`problem_difficulty` 是非代表性标签样本，均不直接决定整题难度或选手掌握度。目录缺失时保留文字名、报告依赖缺失，不编造 ID／难度，不复制目录数据。

## 审核流程

1. 按下述对象协议建立原文对象，确定各对象的适用检查项，保留首尾、附注、引用、图片和代码块的范围。
2. 分别完成已启用的任务并产生对象级结果与依据。宿主支持时可按需委派专项，其余顺序执行。内容核验从定义还原任务，再从输出、样例及边界反查规则。按实际执行记录路线、执行者和委派范围。
   - **内容** 每次读取[内容与专业审核](references/content.md)，审核任务与接受条件、输入输出、范围、操作、数学声明、样例、适用附件及来源合规，并逐步手算样例。
   - **代码（明确要求时）** 作为内容检查项。静态核对附件代码与题面规格的一致性。
   - **文风（启用时）** 每次读取内容 Reference 中的阅读路径及[文风与表达](references/writing.md)，按适用类别核查信息主次、详略与实际阅读负担。
   - **格式（启用时）** 读取[格式审核](references/format.md)，逐类核查全文。有 Python 时运行 Linter、按随附接口裁定候选并补充静态遗漏，不可用时按同一协议处理。
3. 按下述覆盖检查补齐空项及依据不足的结论。已有拒绝理由仍完成其他适用项。
4. 合并所有候选，据原文核实后读取[评价量规](references/rubric.md)去重计分，给出合规与完成状态。撤销或改级保留原文证据，重复发现合并位置与影响。重审说明新增、撤销与改级依据，独立评测隔离历史结论。

## 审核对象与记录

开始详细审核前，固定待审原文和版本，按章节或主要段落列对象，再单列重要声明、关键推导、算法、样例及必要附件。仅在启用代码核验时获取专用于该项的附件，并为每份代码单列 `content.code`。对象使用稳定 ID 和原文位置，保持各部分可追踪。按重要内容拆分，避免逐句建表。

内容任务记为 `content`，启用的文风、格式任务分别记为 `reading`、`format`。每个任务分别产生结果，委派时传递相同对象及适用检查项，记录实际执行者与范围。顺序完成同样保留分任务结果。

每条结果记录对象、检查项、结论与具体依据，状态为已核验、发现问题、未确定或不适用。通过依据应含实际核对的关系或边界；依据不足时定向回查。候选问题单独保留位置和核实结论，最终按根因合并。

## 覆盖检查与补查

1. 对照原文检查对象清单是否涵盖审核范围内的章节、重要段落、声明、样例、附件和需核验的代码，对照核验 Reference 检查适用维度是否齐全。
2. 检查各已启用任务是否有结果，每个对象的检查项是否有结论与依据，候选问题是否已核实，格式结果是否均已处理。
3. 只补查遗漏、未确定和依据不足的对象／检查项。保留已发现候选，撤销或改级以原文证据为据。
4. 合并已确认问题后评分。剩余未核验范围如实报告，审核标为未完成；执行遗漏转为补查任务。

有 Python 时使用随包 `scripts/check_coverage.py` 检查下述记录。无 Python 时按相同字段人工核对。记录齐全仅证明执行覆盖，重要对象是否识别完整、依据是否成立和判断是否正确仍由 LLM 核验。

## 记录接口

内部记录可暂存 `/tmp/review.json`。有 Python 时采用以下 JSON 接口，覆盖工具和格式工具使用各自记录文件。

```json
{
  "version": 2,
  "reading_requested": false,
  "format_requested": false,
  "sources": [{"id": "s1", "path": "/tmp/original.md", "sha256": "原文件字节的SHA256"}],
  "objects": [{
    "id": "p1", "source": "s1", "start": 0, "end": 23,
    "excerpt": "该对象起始处的原文短摘录",
    "checks": ["content.rules"]
  }],
  "results": [
    {"object": "p1", "check": "content.rules", "status": "issue", "basis": "原文未规定空区间是否参与计数", "findings": ["f1"]}
  ],
  "findings": [{"id": "f1", "objects": ["p1"], "status": "confirmed", "basis": "指出缺少定义的原句及其对计数的影响"}]
}
```

- `reading_requested`、`format_requested` 按已确定的任务范围显式填写布尔值。旧版记录（`version: 1`）沿用文风必查的覆盖规则。
- `sources` 列待审稿件和范围内已取得的附件。单独提供且未启用核验的代码文件不列入。题解审核的参考题面可作为外部依据。相对路径基于记录文件目录。保存原始文本快照，按 UTF-8 解码后计算零起点左闭右开的 `start/end`，保留原始换行。`excerpt` 是范围起始处的非空精确短摘录。图示等非文本材料在文字锚点下记录实际检查结果与未取得范围。
- `checks` 在判断前确定，检查项用 `content.`、`reading.` 或 `format.` 前缀，同前缀属于同一任务，后缀标明具体维度。已启用任务的对象范围应覆盖登记来源的全部非空白内容。稿件中的代码块保留位置，代码逻辑检查按范围启用。章节对象负责全段覆盖，重要声明可另建重叠的细对象。新增发现涉及漏列声明时先补对象。
- `results` 按对象与检查项一一对应，`status` 取 `checked/issue/uncertain/not_applicable`，`basis` 非空。不适用须给适用性理由。`issue` 关联已确认发现，`findings` 是候选问题 ID 列表。
- 顶层 `findings` 的 `status` 取 `confirmed/rejected/uncertain`，每项须有原文对象、核实依据且被相应结果引用。确认后的级别、类别、影响和修改建议按报告及评价量规给出。

工具检查引用、字段、源文件摘要、范围及摘录、缺失结果、任务全文范围、未确定状态和未核实候选。输出 `records_complete/incomplete/invalid`，退出码分别为 0/1/2。`records_complete` 表示所列记录齐全，内容结论仍需原文依据支持。未取得材料及未识别的重要声明由主审在第一步补查。

## 报告

默认对话输出 Markdown，仅要求保存时写报告文件。以 `# CPScore · 题面审核` 开头，给合规结论、10 分制评分及档次，注明文风、格式、代码是否启用。已启用范围未完成时说明缺口，分数仅计其中已确认的问题。

按“内容问题”“格式问题”列出已确认问题，文风归入内容；格式任务未启用或无问题时省略相应清单。每项写类别、级别／扣分、位置、短摘录、依据、影响及具体改法，同根因合并并保留各处证据。主线不突出时说明应表达的核心、遮蔽它的内容及调整顺序。样例有误时给实际手算。覆盖记录用于内部查漏。

评价文章质量。平台的 AI 辅助创作资格或披露义务仅凭直接证据核验。注明材料和规则版本，启用脚本时记录脚本版本，可取得时记录模型及推理设置；区分静态核验与实际通过。

## 随包工具

在 Skill 目录运行，Python 3.8+ 标准库。覆盖工具读取上述记录，格式命令用于已启用的任务，接口见[格式审核](references/format.md#来源绑定与合并)。

```sh
python3 scripts/check_coverage.py /tmp/review.json
python3 scripts/check_coverage.py /tmp/review.json --format-scan /tmp/format-scan.json
python3 scripts/format_lint.py /path/to/statement.md
python3 scripts/format_lint.py --decisions /tmp/format-decisions.json /path/to/statement.md
```
