# 题面审核

读取完整题面、约束、样例和必要附件，固定目标读者、材料语言与发布规范。由宿主 LLM 审核，不设人工复核或独立子 Agent；只审核时不修改原题面。

## 流程

1. 按[规格核验](references/specification.md)只凭原稿还原合法输入、操作及接受条件，核对全部实质声明和输入覆盖，逐步手算样例与文字演示。附件按有限获取规则处理；附代码默认只作一次静态对照，不编译、运行或造小数据。不替作者补条件、修正文意或代写关键证明。
2. 按[阅读与修订](references/readability.md)检查人类思维、表达缺陷及全文题外内容；AIGC 判定给具体文本依据，不冒充来源确证或重复扣分。
3. 另按[格式协议](references/format.md)核验源码与可见材料。可用脚本时先扫描，LLM 裁定候选并主动补查未报告的原文，再经来源绑定接口合并计数；候选为空不代表全文通过，静态 Confirmed 不能经接口撤销。
4. 按[评分协议](references/scoring.md)分别给内容与格式结论，合并独立根因和总分。完成其余适用项，即使已发现足以拒绝的问题。保留覆盖状态和重审变化；不能严格确认合规的适用必查项按协议处理，不增加重复审判或投票。

## 可选格式工具

确认已有 Python 3.8+ 和执行能力，在本 Skill 目录运行（仅标准库）：

```sh
python3 scripts/format_lint.py --check
python3 scripts/format_lint.py /path/to/statement.md
python3 scripts/format_lint.py --decisions /tmp/review.json /path/to/statement.md
```

多个 Markdown 可一起传入，逐文件评定；`--rules` 查看规则。读取执行状态、错误、实际扫描范围、版本及 `format_assessment`，复核接口与计分以格式协议为准。脚本不编辑原文、不调用模型、不计算最终材料总分。

没有 Python 或工具失败时不安装环境，LLM 按同一协议继续核验并明确剩余缺口；工具故障本身不扣稿件分。只有 PDF／截图不能证明 Markdown 源码合规，源码扫描也不代表页面已实渲染。

## 交付

默认回复 Markdown，仅要求保存时写报告。以 `# CPScore · 题面审核` 开头，先给评分、档次和完成状态，再分别报告内容与格式。

每项列级别、位置、短摘录、失效依据、影响和最小修改方向，不代写完整规则或证明。人类思维检查说明受阻处或通过依据，样例给实际手算过程。格式使用合并后的类别、Confirmed 次数、级别和代表位置，区分静态证据、LLM 裁定与未确认范围。

无问题时概述关键核验；建议与未决项单列，不把建议当成修复。注明实际材料、脚本版本、执行与未完成范围；重审说明新增、撤销和改级理由。
