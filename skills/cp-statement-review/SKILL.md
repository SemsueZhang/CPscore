# 题面审核

读取完整题面、约束、样例和必要附件，固定目标读者、材料语言与发布规范。由宿主 LLM 裁定，不设人工步骤或独立子 Agent；只审核时不改原稿。

算法知识、洛谷标签和知识门槛统一查询 `CPSCORE_CATALOG`（仓库默认 `resources/algorithm-catalog/`）中的 `catalog.json`；可用 `catalog.py search/get/tag/levels`，无 Python 时读同一 JSON。按 `luogu_tags.relation` 区分同义、较宽与上下文。`knowledge_level` 是知识参考，`problem_difficulty` 是非代表性标签样本，均不直接决定整题难度或选手掌握度。目录缺失时保留文字名、报告依赖缺失，不编造 ID／难度，不复制目录数据。

## 审核流程

完整审核将步骤 1～3 执行两遍，每遍覆盖全部适用内容、文风和格式，分别保留发现与覆盖记录。第二遍重新对照原稿核查，再取两遍发现的并集执行步骤 4。详细合并规则见[覆盖记录](references/specification.md#覆盖记录与重审)。

1. 按[规格核验](references/specification.md)记录定义、任务与接受条件、输入输出、范围、操作边界、数学声明、样例和附件，另查全文语言与投稿内容。默认静态核对代码、逐步手算样例，不代补规则或关键论证。
2. 按[阅读与表达](references/readability.md)检查任务叙述；题面无需讲解解法，执行下述 AIGC 契约，仍须完成内容正误核验。
3. 按[格式协议](references/format.md)扫描、逐项裁定候选，再按规范类别补查全文，记录覆盖和独立位置；用工具时读取[合并接口](references/format-tool.md)，不可用时按同一规范继续核验。
4. 按[覆盖记录](references/specification.md#覆盖记录与重审)补查空项及依据不足的通过／排除结论，再按[评分协议](references/scoring.md)合并计分。已有拒绝理由仍完成其余项；独立问题列全，去重保留证据，不限定报告条数。

## AIGC 执行契约

- 每次读取[文风分类](references/ai-style-patterns.md)，逐类检查全文，含首尾、附注、引用和代码块；记录“确认／未检出／未核验”、位置及依据，疑似句群结合上下文和正常对照裁定。
- 确认任一类，总评首句写 **“本文为 AIGC”**；无需生成记录、全文受阻或内容错误。否则写“未检出明显 AIGC 文风”，未核验范围另注；来源资格另核。
- 确认类别写入“内容问题”，列**类别、级别、位置、短摘录、影响范围、依据、最小改法**。每类至少 Major，同类最高级一次，Fatal 及根因去重依评分协议；标签不另扣分。
- 标题、加粗、列表、一般错字及数学错误本身不触发 AIGC。引用／围栏中的无关助手残留按实际用途核验，不一概豁免。

## 报告

默认对话输出 Markdown，仅要求保存时写文件。以 `# CPScore · 题面审核` 开头，总评依次给 AIGC 裁定、合规结论、分数和档次，再列：

- **内容问题**：紧凑覆盖表交代各维度的状态与依据、阅读通过依据或断点，再列全部缺陷（含文风），无独立文风章节／子分。
- **格式问题**：类别覆盖、未确认范围、合并后的 Confirmed 次数、级别和代表位置；附记录保留全部独立位置及静态／LLM 证据。

缺陷列级别、位置、短摘录、失效依据、影响和最小改法；样例给实际手算。未核验／不适用如实标注，静态判断与实际通过分开。注明材料、规则／脚本版本和执行范围，可取得时记录模型及推理设置。无缺陷仍给必查依据，建议单列；重审说明新增、撤销和改级理由。

## 格式工具

Python 3.8+ 标准库，在本 Skill 目录运行：

```sh
python3 scripts/format_lint.py /path/to/statement.md
python3 scripts/format_lint.py --decisions /tmp/review.json /path/to/statement.md
```
