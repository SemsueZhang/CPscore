# 数据审核

读取题面、题解、参考程序、原测试集与答案、时空限制、判定器、子任务及计分规则。使用宿主已有工具，不依赖其他技能。

## 流程与 Reference

1. 按[数据与执行核验](references/verification.md)固定原集，核对合法性、答案、判定和计分，按独立机制选取错解候选。
2. 先证实候选错误，再核实原集上的实际额外收益。执行、批处理与异常处理沿用同一核验 Reference，不把外加反例并入原集成绩。
3. 按[评分协议](references/scoring.md)以实际漏检影响为主、错解机制为辅，对独立数据缺口定级，给出补点或判定器修正建议。修订后另行实测，分别报告原集成绩、建议和修复结果。

## 交付

默认在对话输出 Markdown，仅用户要求保存时写报告。可使用实测所需源码、临时输入和原生日志，不另建台账或覆盖用户材料。

基于已核实证据集中成稿，保留全部确认扣分点及依据。保存报告与更新 README 等索引分别操作，后续使用局部补丁，避免因索引变化重写整篇。

用 `# CPScore · 数据审核` 开头，先给评分及完成情况。每项说明独立错解机制、证错依据、原集成绩、正常部分分、额外收益及所涉计分单元、分级原因和修正建议。无扣分项时概述实际覆盖。未实测范围、未决疑点与可选补点分开，不编造通过率或数据完备结论。
