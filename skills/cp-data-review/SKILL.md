# 数据审核

读取题面、题解、参考程序、原测试集与答案、时空限制、判定器、子任务和计分规则。使用宿主工具，可独立安装。

算法知识、洛谷标签和知识门槛统一查询 `CPSCORE_CATALOG`（仓库默认 `resources/algorithm-catalog/`）中的 `catalog.json`；可用 `catalog.py search/get/tag/levels`，无 Python 时读同一 JSON。按 `luogu_tags.relation` 区分同义、较宽与上下文。`knowledge_level` 是知识参考，`problem_difficulty` 是非代表性标签样本，均不直接决定整题难度或选手掌握度。目录缺失时保留文字名、报告依赖缺失，不编造 ID／难度，不复制目录数据。

## 流程

1. 按[数据与执行核验](references/verification.md)固定原集，核验合法性、答案、判定和计分，按独立机制选错解。
2. 先证错，再实测原集的额外收益；依同一协议批量执行和处理异常，外加反例不并入原集成绩。
3. 按[评分协议](references/rubric.md)定级独立缺口，提出补点或判定修正。修订须另行实测，原集成绩、建议与修复结果分开。

## 交付

默认对话输出 Markdown，仅要求保存时写报告。可使用实测所需源码、临时输入和原生日志，不另建台账或覆盖用户材料。报告与索引更新分别操作，后续局部修改。

以 `# CPScore · 数据审核` 开头，先给评分和完成状态。列全确认缺陷：独立机制、证错依据、原集成绩、正常部分分、额外收益及计分单元、定级理由、改法。无缺陷时概述实测覆盖；未实测、未决及可选补点分开，不编造通过率或完备结论。
