# 选手能力画像与表现预测

一次核验题目和完整解法，比较能力条件如何改变过程，提炼有效差异；不逐锚点求解或默认输出 16 份报告。

算法知识、洛谷标签和知识门槛统一查询 `CPSCORE_CATALOG`（仓库默认 `resources/algorithm-catalog/`）中的 `catalog.json`；可用 `catalog.py search/get/tag/levels`，无 Python 时读同一 JSON。按 `luogu_tags.relation` 区分同义、较宽与上下文。`knowledge_level` 是知识参考，`problem_difficulty` 是非代表性标签样本，均不直接决定整题难度或选手掌握度。目录缺失时保留文字名、报告依赖缺失，不编造 ID／难度，不复制目录数据。参考区间不自动填写 K 或 D/P/I/B。

## 输入与执行

1. 按[画像协议](references/profiles.md)区分自评、经历证据和假设，按[行为量表](references/levels.md)记录 D/P/I/B，K 按算法 ID 记录掌握度；各轴可同强／同弱／未知，不求总分。接受自然语言、[Markdown](references/profile-template.md)或[JSON](references/profile-template.json)，个人画像直接使用；缺指定选手才用 [16 个假设锚点](references/reference-profiles.json)。
2. 按[共享分析](references/prediction.md)核验题面、约束与完整路线，可复用其他技能有效分析。固定赛制、时长、语言、模板和反馈；逐路线保留知识、发现、证明、实现、调试及资源条件，不跨路线拼最低门槛。
3. 逐画像／路线判断初始尝试、推进节点与瓶颈；区分知识熟练与本题独立发现，陌生方法允许有具体依据的重建，未知保留。
4. 依共享协议按结果、路线、主要原因和进展合并，再提炼语义差异。同果异因保留，无效分数差不强调，不固定组数或为多样性编造结果。交付前执行该协议的预测审查。
5. 需要离线校验／批处理才读[脚本接口](references/script-interface.md)；脚本只校验和诊断，不调用外部 API 或证明预测准确。

## 交付与边界

默认对话 Markdown，仅要求时保存画像／报告。先交代题目、环境、画像来源和未知，再给“能力条件 → 预计路线与进展 → 瓶颈 → 改变结论的条件”。分数须有真实子任务依据；耗时仅按需要、有阶段依据时给粗略范围，不相加互斥路线，团队考虑分工及共享电脑。

自述、实证、假设、推断分开，预测用“可能／预计／若”；无执行证据不称已发现／编码／通过，无校准不给成功率、置信区间或精确耗时。赛前不用本场结果反推，已暴露则标材料回放。

题目难度由 `cp-difficulty-luogu` 另评，材料分、质量分与能力不互换。其他技能可选复用画像和共享分析，不强制依赖或为各画像另建 Skill／Agent。
