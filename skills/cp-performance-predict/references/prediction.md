# 共享分析、条件预测与合并

可供其他 Skill 复用：一次核验完整路线，为各画像预测过程，再合并有效差异；题目难度另评，不逐画像求解。

## 先固定完整路线

逐路线记录约束、算法 ID、发现、正确性与成本、实现调试及进展节点。必要／有帮助知识分开，必要仅指本路线；目录参考先查映射和样本范围，不自动生成门槛或修改画像。不拼接不同路线最轻的发现、证明和实现。

未确认解法只作候选，无完整正确路线则说明分析不足，不给可靠预测；已知完整另解不因非主解而省略。固定语言、时长、模板、反馈，环境变化重评受影响门槛。

给出关键发现后，仍检查中间结论的依赖、分支取舍及不变量衔接，不能因各步局部易懂或 LLM 易于补全就忽略持续推导负担。推导要求按具体任务落实到现有 D/P：后续模型和转化的设计看 D，推导前提、完备性及复杂度论证看 P。题目难度的 R 轴不新增画像字段；篇幅、机械步骤或链长不自动抬高门槛，也不累计成分数。

## 按画像检查过程

先考虑可能的直接枚举、熟悉模型和失败尝试，再对每条路线依次核对：

1. K 是否支持识别和使用具体工具。分类自述是线索，不能补满算法掌握记录。未知信息影响结论则保留条件分支。
2. D 是否支持发现本题具体性质或转化，而非只会该算法。看过题解不算首次独立发现。
3. P 是否支持推导链的前提、必要性、充分性和复杂度论证。猜对公式不能替代证明。
4. I 是否支持这一整条路线的程序、资源与数值范围。
5. B 是否支持发现这条路线易出现的具体错误、构造针对测试并排查。

按实际依赖排序，不强求 K/D/P/I/B 串行。记录“若推进至此还需什么”，上游受阻不声称实际经历下游；进展须为有效观察、算法或真实子任务，读懂题意不算突破。

陌生算法可重建时，给具体步骤、额外 D/P 与时间条件；无法确认则保留未知，不以 K 不足判绝对不可能。适合的完整另解继续保留。

无历史校准只作定性预测，不给成功率；仅需且有阶段负担依据时给粗略耗时，未知不填数字。分数须据真实规则，无部分分赛制只报进展。

## 可选脚本

需要离线校验、批量比较或敏感性诊断时读取[脚本接口](script-interface.md)；脚本不生成解法或替代语义判断。

## 合并与提炼

按预期结果、完整路线、主要障碍和有效进展合并，忽略不改变这些结论的分数差异；同结果异因／异路线及真实部分分须保留。画像 ID 仅追溯，不作类别或统计权重。

同瓶颈仅程度不同可合并列条件范围；影响解释的路线、原因、得分、未知条件和部分分依据仍分开，即使只适用一个画像。无固定组数，确无差异仅给一条。

按“能力条件 → 可能路线与阶段 → 瓶颈 → 改变判断的条件及未知”给简短结论、来源和环境，尽量说首次尝试，不写成实际发现／编码／通过。被请求的题目难度另按难度 Skill。

## 预测审查

交付前逐项核对，不能只列勾选表：

1. 结论是否引用了这道题的性质、约束和完整路线，而不是通用能力描述？
2. 是否把知识熟练、独立发现与发现之后的推导负担分开，陌生算法是否允许有依据的推导可能？
3. 是否保留适合不同画像的完整替代路线，未拼接各路线最低门槛？
4. 每项预测差异能否指向具体任务或错误风险？
5. 合并是否掩盖关键路线、失败原因、未知条件或部分分依据？
6. 分数变化是否仅触发形式化阈值，缺少真实的过程变化？
7. 不同题型是否仍机械地输出同样几组“强／中／弱”？
8. 是否把推断写成事实、把自评写成测量、伪造执行或精确概率？
9. 差异有效性：固定其他信息，对相关能力作小幅改变，具体瓶颈是否合理变化？无关能力可以不影响结果。

`--details` 仅扰动已知 D/P/I/B 和本题引用的算法掌握度，未知保留，报告改变的门槛；只诊断差异，不证因果／准确性。阈值不足应改分析或降低确定性，不为显示差异改画像。

真实预测校准需另做有赛前画像、封存预测和独立实际表现的留出评估。本文案例仅检查规则一致性与可解释性。
