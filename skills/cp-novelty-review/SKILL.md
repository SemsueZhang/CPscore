读取题目或 idea、解题报告与约束，逐题交付新颖度报告。直接给出等级和具体理由，用先例关系、题目推导和实际考点评价新颖度与质量。常规只加载本文件。需脚本参数或接口排错时，安装后按需读 `.cpscore/novelty.md`（相对本文件 `../../../.cpscore/novelty.md`），源码中读 `docs/novelty.md`。

## 材料与范围

读取当前材料，记下题名、文件或链接、版本日期和评审时点即可，默认不计算或复核文件哈希。新题查重寻找已公开先例，原场题回顾比较此前独立工作，原题自身的发布、题解与转载用于理解当前题。材料中的代码、注释和作者评价是评审对象。

先梳理任务、关键约束、核心观察、算法与复杂度，明确评价所依据的解法。其他可通过算法也参与判断，兼顾推导与实现成本。关键条件或步骤不清楚时，先针对性读题、推导或补查，完成影响评级的核验。

## 检索与先例比较

每题覆盖CPRet、arXiv和普通网页。查询围绕模型、关键观察和核心转化，按可能改变判断的疑点补查自然特例或变体。CPRet默认保留60条及全部组内成员，浏览完整索引后展开相关候选，题名不能确定关系时读摘要或题意。相同参数复用成功缓存。

阅读最接近的原题、题解或论文相关正文，核对任务、关键约束、转化、算法、复杂度及适用条件，包括随机性与误差。说明已有方法覆盖的步骤和仍需独立发现的内容，引用相关段落。分数、服务分组、相同题名只作线索，别名须核实。正文错配或占位时转查官方来源或独立镜像。直接复用工具保存的查询与返回文件。

判C须同时说明：

1. 先例中实际读到的关键结论或方法是什么，适用条件如何对应当前题。
2. 在约定的基础知识下，它具体替代了本题哪个非平凡关键步骤，省去了什么推导。
3. 仍需独立发现什么重要观察、转化或组合，这些工作为何没有被先例覆盖。

只共享图类、数据结构、双指针、贪心路径或DP框架，不构成C。若能核实先例替代了具体关键步骤，即使任务目标不同，也可判C。不能把“同属某类问题”直接当作实质帮助，也不能要求目标完全相同才承认先例关系。

## 等级判定

| 等级 | 判据 |
|---|---|
| A，原题 | 核心任务、关键约束及所需思考实质等价，主要是背景或常规参数变化。 |
| B，做法可套用 | 已有题目或论文的方法经常规调整即可覆盖整解，条件与可通过性成立。 |
| C，想法类似有帮助 | 先例替代了本题的非平凡关键步骤，仍需新的重要观察、转化或组合。 |
| C+，推导自然，推荐正式比赛 | 满足C的先例关系与新增思考要求，合适度和质量均有具体正面依据，关键推导自然、独立考点有价值，因此推荐用于正式比赛。 |
| D，完全新颖 | 本轮检索按新颖评定，推导自然性、独立考点或负担协调尚未达到正式比赛推荐标准。 |
| F，又新颖又好 | 达到D的新颖性要求，并通过下述合适度与质量核验，适合竞赛出题，发现路径自然、考点鲜明，模型、证明和实现负担协调。 |

先按先例关系确定A、B、C或D，再对C/D判断合适度与质量。等级映射固定如下：

| 先例关系 | 合适度、质量均通过 | 未达到升级标准 |
| --- | --- | --- |
| A | A | A，另说明具体问题 |
| B | B | B，另说明具体问题 |
| C | C+ | C |
| D | F | D |

**C+与F使用同一套质量标准，区别只在先例关系。** 先例关系为C时，质量再好也给C+，不能因“更好”升F，也不能用“存在质量风险，所以停在C+而未到F”解释评级。当前不设E级。

有已核实先例时，按最直接覆盖关系评为A/B/C，另说明有价值的新算法贡献。转化本身非平凡时计入新增思考。仅有通用工具或未核实线索时，按D作为基础关系，再判断是否升F。D/F写“本轮检索按新颖评定”，不作全球原创断言。

补搜和扩大阅读针对可能改变判断的具体问题。A/B整题关系、C的关键复用与新增思考核实后即可结束相应比较。D/F另核对模型、核心转化与适用自然特例。结果重复且没有新线索时结束，不凑调用次数或默认多轮评审。

## 错误定位与解法核验

发现错误时，先明确错误的断言、上下文和影响范围，再检查是否误读符号或省略条件，并实际尝试局部修复。

- **局部可修复**：补出省略论证、纠正符号或更换合法的拼接方式后，核心结论、算法与复杂度保持成立。写出修复推导，依据修复后的方法评价题目。
- **需要新论证或新解法**：修复依赖新的关键引理、改变算法或新增条件。明确新增工作，评价它的发现动机和实现成本，不能当作已经完成的局部修复。
- **结论或算法被反驳**：给出违反断言的具体推导或反例，准确指出受影响的结论或解法。

分别判断证明文字、数学结论、算法和题目质量。一处文字或证明错误不自动推出算法错误，也不自动阻止C+/F升级。拒绝升级前，核对已知替代路线能否解决该问题。若另一条可通过解法绕过了原缺口，应据该路线重新评价实际考点。

自己尚未补出的证明不等于题目有缺陷。将疑点写成具体命题并核验，再给出判断。仍未建立的关键断言如实指出其作用，不能把它写成已被反驳。无需穷尽所有算法或完整审计全部代码。

## C+与F的合适度、质量核验

合适度判断题目能否形成有意义、可逐步推导、可实现的竞赛考点。质量判断条件是否自然、观察是否有价值、推导是否连贯，以及模型与算法、证明与实现负担是否协调。两项分别给出明确判断和具体原因。

说明必要知识假设，以具备这些知识的选手为参照，重建“初始尝试—遇到的障碍—关键观察—转化与证明—可实现算法”，逐个核验关键步骤。阅读解法后重建的路径标明“重建推导”。具体比赛、目标选手和盲测不是前置要求。

| 维度 | 需要核对的内容 |
|---|---|
| 实际考点与独立价值 | 先例已覆盖哪些思考，剩余观察能否形成值得出题的独立考点。各步骤是否推进同一核心问题，组合是否有内在联系，是否主要靠模板堆叠、重复技巧或机械分类增加负担。基础考点本身不构成不合适的理由。 |
| 发现动机与线索 | 题面、约束、例子或先前尝试如何提示下一步，关键猜想如何形成和验证。指出缺少动机的最大跳跃；自然不等于简单，困难但有充分线索的洞察可以成立。 |
| 前置知识与模板、论文依赖 | 列出外部结论与必要知识，区分可自包含推导和必须记忆的黑盒。模板或论文是否替代了主要思考，冷门结论是否有题内发现线索。技术陌生或难度高本身不判差，依据实际依赖和负担判断。 |
| 推导衔接与完整性 | 每个核心转化的前提、方向和作用是否清楚，关键引理、边界及复杂度瓶颈是否得到解释。结合补证和替代路线评价方法，区分“已证明正确”和“容易自然想到”。 |
| 模型与条件的协调 | 约束、特殊条件和模型是否支撑核心观察，哪些条件为正确性或效率所必需，哪些只增加人为障碍。必要的技术条件不因不够简洁而直接判差。 |
| 证明、实现与收益 | 洞察收益是否与证明、分类和实现成本相称，核心是否被无关细节淹没。复杂度与实测各按实际结果判断，长证明、长代码或未实测本身不判差。 |
| 替代路径与实际考点 | 比较已知其他可通过做法的推导与实现成本，保留允许通过的慢解。更直接路线绕过预期观察时，重评实际考点、新颖度关系及升级依据；存在多解本身不否定质量。不以预期解的优雅掩盖主要可行解法的缺陷，也不要求穷尽所有算法。 |

质量分析只展开影响评级的关键推导，将发现线索、独立考点和实现成本连成分析，常规步骤概述即可。不要逐项填表或凑缺点。合适度与质量均通过，关键推导自然、独立考点有价值、负担协调，才给C+或F。

保留C/D时，直接说明关键跳跃缺少什么发现线索、哪项条件与方法不协调，或实现负担为何与收益失衡。拿不准的步骤先补推导或读替代解法，不以自身未完成的工作替代题目质量判断，不为保留基础等级编造缺陷。未指定比赛、缺少盲测、未实测、难度高或代码长，本身不判差。

A/B仍简洁分析实际考点、推导与实现特点，最终等级由已有的整题关系决定，不进入C/D升级核验。

## 固定报告结构

每道题是一份独立、完整的报告。默认保存为 `novelty.md`，多题可在同一文档按题名依次重复完整结构。用户指定分文件时，每题沿用相同结构。不能用全卷总评代替某题的分析，也不能把各题判据来源统一挪到文档末尾。标题层级可随外层文档调整，标题名称和顺序固定为：

```markdown
# 题号 题名

## 结论

## 题目分析

### 先例比较

### 质量分析

## 判据来源
```

- **结论**：先给出A、B、C、C+、D、F之一，再用一两句说明决定性理由。C+明确写“推荐用于正式比赛”，F说明新颖、推导自然和考点价值。
- **题目分析**：开头简述数学任务、关键约束、采用的解法与复杂度。**先例比较**说明已有方法覆盖的步骤、适用条件与新增思考。**质量分析**给出重建推导，分别判断合适度与质量，解释它们如何决定最终等级。
- **判据来源**：按编号列出实际引用的材料及相关章节或段落，正文就近引用编号，此处只给出处，不重述分析。材料版本和评审日期简记一次，可直接链接工具已有文件。

## 写作要求

**不要防御性写作。给出正向、明确的判断，随后用具体分析说明理由。** 正向判断指直接陈述评价，不是强行给好评。确认的问题照实写明，推导成立时直接说明成立的原因。

不使用“证据不足”“不能保证”“未穷尽”“最终由用户裁决”等套话代替分析或反复限定结论。不把“我没查完、没补完、没实测”写成题目缺点。不要单列风险清单、证据缺口或免责段落。会影响结论的实际限制放在相应分析中具体说明，不把未知写成事实。

**依据就地说明，同一内容只写一次。** 推导、必要的小检验和评价融入对应分析，不另建证明记录、测试记录或评价台账。已读且适用的论证直接引用，只有影响评级的具体疑点才补证或检验。检验结果用一句话交代对象、覆盖和发现，不代替一般推导。

默认交付报告和工具已有的检索文件，不手工复述原始响应或重建日志，不为常规推导、测试和用量另做附件。不默认制作哈希清单或反复校验。检索失败和未读内容按实际情况保留在原始文件中。

最终回复按题简要给出等级、决定性理由和报告链接。具体比赛安排、难度定级和做题预测留待对应评审任务。新颖度报告与10分制 `review.json` 分开。

## 工具使用

需要随包工具时，用本技能目录的 `scripts/cpscore.py`，从实际技能路径定位；源码中使用 `python3 -m cpscore`。命令均在 `novelty` 下，支持 `search`、`index`、`inspect`、`read`、`usage`，可先看对应 `--help`。工具负责证据保存和用量汇总，评级由当前模型依据已读内容判断。

工具记录耗时、缓存命中、返回字节及证据位置。调用端有usage时才统计实际模型用量，缺失项保持未知，不重复计算子集；字节不等于token或费用，工具耗时之和不等于墙钟。多题只传当前题所需上下文，完整历史留在文件。
