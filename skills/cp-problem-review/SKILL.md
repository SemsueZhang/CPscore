# 题目总评

读取题面、全部声明正确的做法、题解、std、约束、子任务、数据和已有评审。按[总评协议](references/assessment.md)独立审核或复用可靠评审，不依赖其他技能。复用前核对材料版本及旧问题的修复依据。

## 材料与设计审核

- **材料质量**：确认题意唯一、题面易读、样例正确、算法与实现覆盖全范围，关键证明充分。题解的推导、衔接和表达应可理解，std 的记号、状态、公式、更新依赖和阶段应与题解清楚对应。具体判级边界见总评协议。
- **数据**：核验合法性、答案和判定计分。漏网须同时证实候选错误与原集实际额外收益，正常部分分不算漏洞。
- **解法空间**：分析自然尝试、障碍、更简单路线、非预期解和漏洞，核验可行路线的正确性及全范围复杂度。
- **子任务**：特殊条件和分值是否形成有意义的进阶，各做法可得哪些分数，有无意外跳档或错误依赖。无需部分分时说明理由。
- **满分路线与设计**：发现线索、知识、证明和实现负担是否协调，条件是否支撑有价值的观察，限制是否误伤合理正确解。难、代码长或多解本身不判差。

需要新颖度评价时，用宿主检索并阅读最接近的原题或论文，比较任务、条件、可复用步骤与剩余独立思考，按总评协议评级。未检索不算完成，也不宣称全球原创。

对疑点尝试补证、反驳或局部修复。未证实疑点不当作缺陷，有限测试不构成一般证明，未找到替代解不等于不存在。

## 交付

默认在对话输出 Markdown，仅用户要求保存时写报告，不另建中间记录。先给题名、总评及决定性理由，再以材料问题、解法空间和设计分析支撑结论，最后给修改建议。已有分项可用简表汇总。

引用具体材料与必要推导，说明缺数据、检索或执行条件造成的具体未完成项，不伪造实测或把建议当作已修复。
