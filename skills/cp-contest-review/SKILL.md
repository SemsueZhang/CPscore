# 比赛总评

默认赛前评价。读取完整题面、参考解法、已有设计评审和比赛要求，固定目标选手、赛制、时长及计分规则，注明必要假设。使用宿主工具，可独立安装。

算法知识、洛谷标签和知识门槛统一查询 `CPSCORE_CATALOG`（仓库默认 `resources/algorithm-catalog/`）中的 `catalog.json`；可用 `catalog.py search/get/tag/levels`，无 Python 时读同一 JSON。按 `luogu_tags.relation` 区分同义、较宽与上下文。`knowledge_level` 是知识参考，`problem_difficulty` 是非代表性标签样本，均不直接决定整题难度或选手掌握度。目录缺失时保留文字名、报告依赖缺失，不编造 ID／难度，不复制目录数据。

## 流程

1. 按[赛前预测](references/prediction.md)隔离本场成绩和赛后反馈，核对旧评审版本与依据；仅明确要求复盘时使用实际结果，已暴露结果按协议标记。
2. 理解完整可通过路线，按能力层次重建可行题组、分工、共享电脑排程、剩余时间和后续机会，比较顺利、通常、受阻情形；优先核验影响梯度的未知解法。可选复用 `cp-performance-predict` 的画像／锚点及共享分析，再提炼有效差异，无须逐画像求解或交付 16 份报告；未安装时按本地协议工作。
3. 按[整套判定](references/assessment.md)给逐题档次、占比与整体否决依据；外部质量等级先核对现行标准。组合调整后重查受影响路线和排程，建议不算已调整。

## 交付

默认对话输出 Markdown，仅要求保存时写文件。先给赛前总评与决定性理由，再说明选手、条件、材料和结果暴露情况。逐题简表与分层摘要交代可达题组、后续候选、剩余时间、瓶颈及情形变化。

列三档题数、占比和触发条件，再给调整优先级。未知项不强行定档；正文聚焦断层与有效过渡，未完成项就地说明。预测与实测区分，实测注明来源，不编造通过率或反馈。
