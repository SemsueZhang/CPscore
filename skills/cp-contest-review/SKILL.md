# 比赛总评

默认任务是在比赛开始前评价题目组合。读取完整题面、参考解法、已有设计评审与赛前比赛要求，按[总评协议](references/assessment.md)预测。先确认目标选手、赛制、时长和计分规则，必要假设明确写出。

不查用目标比赛的榜单、成绩、提交记录、奖牌线或赛后反馈反推难度，混合材料只取题意与数学解法。已结束比赛也按赛前边界回放；仅用户明确要求复盘时另用实际结果。

使用影响理解、合理解法通过、判定公平与有效思考的材料证据，不展开逐项审计或以普通措辞、排版、注释问题主导结论。

## 单题与组合

复用评审前核对版本、问题影响并排除赛后评级，不直接映射材料最低档或新颖度字母。理解可通过路线及发现、证明、实现负担，按本场作用判档。可独立推导，审查者未解出不算质量或难度证据。

按本场要求评价：

- **区分度**：声明各层先修知识，预测总时长内的可行路线及下一题、下一档得分，检查断层、共同瓶颈和闲置题位，用关键观察与负担支撑判断。
- **做题体验**：重建首次读题至切题的过程，计入失败尝试，比较反馈、方向、协作和机时。三人并行思考仍共用电脑，不能相加各题独立最优时间，或用已知题解的编码时间代替首次完成时间。难、代码长、交互或通信本身不判差。
- **整体质量**：考点与推导是否有价值，知识、证明、实现是否协调，形式是否互补，同模型多题是否有独立思考，题数和分值是否服务比赛目标。

区分度须落实为“选手层次—题目可达性—完成一组题后的下一步”，具体方法见总评协议的“区分度分析”。先识别各层在合理排程下可能完成的题组，再检查剩余时间内有哪些独立可达的后续路线，做乐观、通常和受阻情形的比较。优先补齐可能承担过渡作用的未知解法，不用单题质量占比、算法标签或一个理想的全场排程替代区分度判断。

可用本场结果之外的既有背景与历史校准，说明适用范围；无校准时给路线支持的粗略区间，不编造通过率或名次。明示读解法后的路线重建，不额外盲测。已看过本场结果时，按协议披露暴露情况并重审依据，不称独立盲预测或准确率证据。

## 交付

默认在对话输出 Markdown，仅用户要求保存时写报告。先给赛前总评与决定性理由，再说明目标选手、比赛条件、材料范围和结果暴露情况，以逐题简表及各层可行路线支持区分度与体验预测，列明三档题数、占比及触发的判定条件，最后给调整优先级。未知项保留为未知，不为凑齐占比强行定档。

对区分度给出一张紧凑的分层摘要：可能完成的题组、主要后续候选、剩余时间与瓶颈、不同情形下的变化。正文围绕影响结论的断层或有效过渡展开，不堆叠内部分析表。

用宿主已有文件、检索和执行工具，具体说明未完成项。预测标明为预测，实测注明来源，不编造通过率或反馈。
