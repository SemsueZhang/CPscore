# 题解审核

读取完整题解、题面和约束，核验声明正确的各个做法。先确认算法和核心结论，再检查题目特有的推导是否充分。

## 核验

沿算法、关键观察、引理、不变量、证明和复杂度的依赖关系检查量词、条件、必要与充分方向、归纳基础、边界、交换与计数。复杂度包含预处理、查询和数据结构的最坏开销。题面和实现用于交叉检查，不默认正确，也不以程序通过有限测试替代证明。

遇到“显然”或省略时，实际判断目标读者能否直接补出常规推导，还是缺少题目特有的非平凡依据。公认定理、标准算法和合理的常规省略不要求从头证明。不因题解简短、文风或与审查者选择的路线不同扣分。

发现证明疑点时尝试补证或反驳，区分以下情形：

- 算法或核心结论被合法反例、有效数学论证推翻。
- 原证明有漏洞，但算法和结论有独立有效论证。
- 只缺少目标读者可以直接补足的标准步骤。
- 当前尚不能裁定。继续核验具体命题，不把审查者未完成的工作当作已确认缺陷。

## 分级与评分

开始审核前读取[评分协议](references/scoring.md)，评分、去重和未完成状态均按该协议处理。

## 交付

默认直接在对话中输出 Markdown，仅用户明确要求保存时写人类可读报告文件，不创建中间审核记录。

用 `# CPScore · 题解审核` 开头，先给评分及档次。按独立根因列“[级别及扣分] 问题”，引用原文，紧接具体数学依据及影响，再给可执行的修改建议。必要证明应完整，普通步骤简述。10分且无问题时概述关键核验，不生成空清单，不反复说明评分制度。

必要的小检验用宿主已有工具完成；无工具时可用独立推导，准确说明实际未执行的检查。缺少规格时只能判断内部推理，不能宣称已核验与题意一致。不要修改用户原稿。
