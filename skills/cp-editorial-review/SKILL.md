# 题解审核

读取题面、全部约束、完整题解及其中声明正确的所有做法，固定目标读者和投稿规范。只依据原稿裁定，不替作者补条件、改算法或补关键证明。由宿主 LLM 审核，不设人工步骤或独立子 Agent；只审核时不修改原稿。

## 流程

1. 按[数学与内容核验](references/verification.md)一次顺读，逐项核对实质声明的前提、依据、正确性和用途，确认覆盖整个输入域、数值范围与总成本。逐步手算样例，代码只作一次静态对照，默认不编译运行。
2. 按[教学与表达](references/pedagogy.md)检查人类思维、表达缺陷及全文题外内容。AIGC 判定给文本依据，不冒充来源确证或重复扣分。
3. 另按[格式协议](references/format.md)核验源码和可见材料。可用脚本时先扫描，LLM 裁定候选并主动补查未报告的原文，再经来源绑定接口合并计数。候选为空不代表全文通过，静态 Confirmed 不能经接口撤销。
4. 按[覆盖记录与重审](references/verification.md#覆盖记录与重审)核对遗漏及结论变化，再按[评分协议](references/scoring.md)合并独立根因、给总分及合规结论。分别完成内容与格式；即使足以拒绝，仍完成其他适用项，不以格式发现数量代替内容覆盖，不增加投票或重复代码验证。

## 可选格式工具

确认已有 Python 3.8+ 和执行能力，在本 Skill 目录运行（仅标准库）：

```sh
python3 scripts/format_lint.py --check
python3 scripts/format_lint.py /path/to/editorial.md
python3 scripts/format_lint.py --decisions /tmp/review.json /path/to/editorial.md
```

多个 Markdown 可一起传入，逐文件评定；`--rules` 查看规则。读取执行状态、错误、扫描范围、版本及 `format_assessment`，复核接口与计分以格式协议为准。脚本不编辑原文、不调用模型、不计算最终题解总分。

没有 Python 或工具失败时不安装环境，由 LLM 按同一协议继续核验，记录剩余缺口；工具故障本身不扣稿件分。只有 PDF／截图不能证明 Markdown 源码合规，源码扫描也不代表页面实渲染。

## 交付

默认回复 Markdown，仅要求保存时写报告。以 `# CPScore · 题解审核` 开头，先给合规结论、分数与档次，再分别报告内容和格式。

内容问题列级别、位置、短摘录、失效依据、影响及最小修改方向，指出具体缺失条件、分支或推理，不代写完整证明或解法。人类思维检查给受阻步骤或通过依据；样例列实际手算及未完成范围。格式引用合并后的类别、Confirmed 次数、级别和代表位置，区分静态证据、LLM 裁定和未确认范围。

无问题时概述必查范围的依据；建议单列，不当作修复。注明实际材料、脚本版本和执行范围，重审说明新增、撤销与改级理由。静态代码对照不代表编译、实测或评测通过。
