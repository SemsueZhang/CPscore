# 题解审核

读取题面、全部约束和完整题解，纳入部分分、超时、卡常及附录方案，固定目标读者与投稿规范。核验采用两条互补路线：**正向递推**从题面条件和定义出发，逐步核对论证、算法、复杂度、实现及样例；**逆向思考**从结论、代码和样例反查所需前提与论证，主动寻找边界遗漏、矛盾和反例。主智能体统筹并尽可能将两条路线分别交给不同子智能体；可用子智能体不足时，由主智能体完成未委派路线，并按边界继续分派教学表达／AIGC、格式等任务，以减少漏项。汇总时核对覆盖、裁决冲突、合并同根因，主智能体对完整审核及最终报告负责。只审核时不改原稿。

## 审核流程

完整审核将步骤 1～3 执行两遍，每遍覆盖全部适用内容、文风和格式，分别保留发现与覆盖记录。第二遍重新对照原稿核查，再取两遍发现的并集执行步骤 4。详细合并规则见[覆盖记录](references/verification.md#覆盖记录与重审)。

1. 按[内容核验](references/verification.md)逐做法记录定义、数学结论、原文论证、输入边界、总成本、数值、实现及样例，另查题意转述、全文语言与投稿内容。默认静态核对代码、逐步手算样例，不代补条件、算法或关键证明。
2. 按[阅读与表达](references/pedagogy.md)检查解题主线，执行下述 AIGC 契约，仍须完成内容正误核验。
3. 按[格式协议](references/format.md)扫描、逐项裁定候选，再按规范类别补查全文，记录覆盖和独立位置；用工具时读取[合并接口](references/format-tool.md)，不可用时按同一规范继续核验。
4. 按[覆盖记录](references/verification.md#覆盖记录与重审)补查空项及依据不足的通过／排除结论，再按[评分协议](references/scoring.md)合并计分。已有拒绝理由仍完成其余项；独立问题列全，去重保留证据，不限定报告条数。

## AIGC 执行契约

- 每次读取[文风分类](references/ai-style-patterns.md)，逐类检查全文，含首尾、附注、引用和代码块；记录“确认／未检出／未核验”、位置及依据，疑似句群结合上下文和正常对照裁定。
- 确认任一类，总评首句写 **“本文为 AIGC”**；无需生成记录、全文受阻或内容错误。否则写“未检出明显 AIGC 文风”，未核验范围另注；来源资格另核。
- 确认类别写入“内容问题”，列**类别、级别、位置、短摘录、影响范围、依据、最小改法**。每类至少 Major，同类最高级一次，Fatal 及根因去重依评分协议；标签不另扣分。
- 标题、加粗、列表、一般错字及数学错误本身不触发 AIGC。引用／围栏中的无关助手残留按实际用途核验，不一概豁免。

## 报告

默认对话输出 Markdown，仅要求保存时写文件。以 `# CPScore · 题解审核` 开头，总评依次给 AIGC 裁定、合规结论、分数和档次，再按“内容问题”“格式问题”分组列出全部已确认问题；无问题的类别不列空清单。不输出核查项、通过项或未发现问题的覆盖表。

每项写明级别、位置、短摘录、失效依据和影响，并给两类建议：针对该处的具体修改方向，以及今后写作时避免同类问题的方法。相同根因或写作方法可合并表述，但须保留各处证据；文风问题纳入内容问题，不另设章节或子分。样例有问题时给实际手算。仅在未核实范围会影响结论时说明；区分静态判断与实际通过。注明材料、规则／脚本版本和执行范围，可取得时记录模型及推理设置；重审说明新增、撤销和改级理由。

## 格式工具

Python 3.8+ 标准库，在本 Skill 目录运行：

```sh
python3 scripts/format_lint.py /path/to/editorial.md
python3 scripts/format_lint.py --decisions /tmp/review.json /path/to/editorial.md
```
