# 题解审核

读取完整题解、题面与约束，核验所有声明正确的做法。使用宿主已有工具，不依赖其他技能。

## 流程与 Reference

1. 按[论证与表达核验](references/verification.md)追踪算法、证明和复杂度的依赖，沿目标读者的阅读顺序定位理解障碍。
2. 对具体疑点尝试补证、反驳或必要小检验，再用题面和实现交叉核对，不默认任一材料正确。逐条读取[本地题解规范](references/luogu-standard.md)中完整收录的正文与示例，检查适用的内容与格式，无需打开洛谷网页。投稿时才展开图床、折叠及来源资格等条件，其他平台说明差异。
3. 给出局部补证或改写，复核其前提、结论、复杂度及上下文。按[评分协议](references/scoring.md)区分算法错误、证明缺漏、表达与规范问题，去重并判断完成状态。

## 交付

默认在对话输出 Markdown，仅用户要求保存时写报告，不创建中间审核记录或修改原稿。

用 `# CPScore · 题解审核` 开头，先给评分及档次。每项写“[级别及扣分] 问题”、原文位置、数学依据、具体理解障碍或规范条款、影响与修改建议。必要补证完整写出，常规步骤简述。规范问题注明适用条件，来源违规注明证据及其性质，不把审核者补证当作原稿已有内容。

无扣分项时概述正确性、复杂度、讲解与规范的关键核验，不输出空清单。可选建议、未决疑点与未核验范围分开。
