# 数学与内容核验

按交付材料审核。未说明节选时，不因截图／从中间开始而假定前文补齐定义或主线；明确节选则限定范围。外部材料不足与原文可确认的讲解缺陷分开。

## 声明、依据与完整解法

对照原题检查稿内转述、约束、取模、复制样例和方案范围的改变／遗漏，不强求题解重抄题面。

逐条从题目条件、原文定义和已建立的结论出发，自行推演每个定理、性质、引理、不变量及复杂度或优化声明。原文给了证明就逐步核对，省略证明或只写了结论也做同样的推演。同段独立声明分别查，核对各自的适用前提和用途。以目标读者的先修知识为准，允许省略公认事实和常规一步推导。

每遇到一个非显然的跳步，核对原文是否给出了足够依据。确认缺证时，指出声明所在位置、已有前提、尚未建立的结论，以及应补的关键理由或适用条件。审核者自行补出推导时，仍记录原文缺证。分别判断结论是否成立、原文推导是否有误、原文论证是否完整。

例如，题解描述双指针算法并直接报 $O(n)$，若线性界依赖内层循环的摊还分析，应说明右指针为何跨外层迭代不回退、其可达范围及每次推进的代价。若原文已说明外层枚举 $n$ 次、每步为常数开销，且右指针始终在 $[1,n]$ 内单调前进，则线性界可直接推出，可省略单列证明。

| 核查对象 | 关键核验 |
| --- | --- |
| 定义与指代 | 状态、非标准函数、聚合量各自作用于什么对象；下标、范围、更新时刻及后续用途是否一致。`sum(j)` 即使函数名常见，也须能确定对哪些对象的哪个量求和；换成求和符号不能补足对象定义。上下文已经明确时不要求重复释义。 |
| 数学结论 | 逐项核对等式、不等式、等价变形、量词、必要与充分、取整及计数，检查边界或手工反例。区分结论为假与原文未证明。 |
| 原文论证 | 归纳、交换、贪心、状态转移和不变量是否支持所声称的结论；题目特有的非平凡联系是否缺失或循环论证。 |
| 完整方法与覆盖 | 仅据原文复述状态、初始化、操作／转移与终止，对照声明范围内的全部合法输入；检查最小／最大参数、零值、重复、空对象及特殊结构等相关边界。不得代补分支、条件、初始化或更换算法后判原稿成立。 |
| 总成本与优化 | 按题目约束核算预处理、状态数、各独立枚举、单步、全部查询和多测总量。核对原文给出的计数、单步代价与大 $O$ 结论是否对应。若表达式本身是有效上界，但原文声称它由某推导得到、该推导实际给出不同结果，记录为复杂度表述与推导脱节，不将其说成大 $O$ 符号或上界本身错误。有效松上界的评分边界见量规。另一算法的性能不能替原文作依据。 |
| 数值范围 | 检查中间乘积、累加、差值、移位、取模前计算及类型转换，不能只查最终答案。对题解描述会执行的计算，即使结果未使用，也核对数值范围。 |

部分分按声明子范围核验。超时、卡常、不能通过和附录方案仍检查数学、论证与成本。明确展示的错解核验错因、反例及其余声明，不要求修成正确解。未核实的分数、通过记录及“只是卡常／仅因 TLE”标为作者自述或待核验。

数学结论、原文论证、代码及实际通过分开判断。必要时推算或手工反驳，指出缺口与后果，不代写完整解法。正文须独立讲清核心分析；实现无额外信息可不附代码，代码／注释／外链仅补充。

复杂度计数与有效松上界的对照见[量规示例](rubric.md#内容定级)。

## 代码静态对照

仅在用户明确要求时执行本节。静态顺读每份实现，对照状态、操作、循环／数组边界、初始化／清空、类型、异常及输出，检查作用域、容器索引和修改后结构有效性。明确片段不强求程序外壳，完整提交检查定义／语法；正确输出不消除正文／注释错误。

代码的资源开销仅核对渐进时间与空间复杂度。能指出具体代码及适用输入，证明实现的复杂度与题解声明不一致时，才报告复杂度错误。常数因子、评测时限和栈容量等实际运行因素不作为代码判错依据。例如，递归 DFS 在链上有 $n$ 层调用，若题解声明 $O(n)$ 辅助空间，代码符合该声明。若题解声明 $O(1)$ 辅助空间，报告复杂度错误。

具体疑点与覆盖空项定向回查，溢出／漏分支与对应覆盖根因依[评分协议](rubric.md)合并。

除用户另行要求代码验证外，不编译、运行、造小数据或对拍，也不启动求解流程；格式脚本除外。

## 文字样例逐步手算

逐一手算样例解释、操作序列、图中演示及正文举例的初始条件、每步合法性、状态更新、中间值和结果，对照原文各步声称。最终输出正确不能证明过程正确；未给过程时核验结论，不强制补简单步骤。

图示或样例未取得、过程未核完时，注明受影响范围。

## 全文、图片与来源

启用文风审核时，按[文风与表达](writing.md)核查正文语言与题外表达。

确认图片清楚且可取得；引用他人文字、图、代码或特有推导须可追溯，不从缺链接推定抄袭，标准算法不强制外链。检查是否整篇复制长题面。启用代码审核时另查代码可读性及防抄袭干扰。

投稿平台设有 AI 辅助创作资格或披露要求时，对照适用条款和作者声明、生成记录等直接证据核验来源合规。

## 教学与阅读路径

目标读者为已读题面、掌握预期先修知识，但不知道本题解法。

### 解题主线

沿原文检查：正在解决什么目标或障碍，引入的量表示什么、为何有用，各步变形怎样推进目标，最后为何得到答案。重点核对本题特有的联系，允许公认事实与常规一步推导省略。

核对定义、前提与论据，定位实质缺失、非平凡跳步和结论错误。报告原句、已有信息、缺失联系及影响。核心内容缺口按[内容量规](rubric.md#内容定级)定级。信息组织和表达的阅读负担在文风启用时核验。

## 内容对象与记录

按[入口对象协议](../SKILL.md#审核对象与记录)为每种做法的适用维度、重要声明和样例分别建项。正向从条件核对结论，逆向从结论反查前提、边界及反例。启用代码核验时再以实现反查。已启用的文风与格式任务各自记录结果，覆盖检查发现空项后定向补查。

内容按对应核验 Reference 给每种做法或规格对象安排适用维度，分别记录定义、数学结论、依据、输入／操作边界、成本、数值及样例。采用正向与逆向路线互补，重要声明各自有结论。无附件／无某类结构等有依据时记不适用。
