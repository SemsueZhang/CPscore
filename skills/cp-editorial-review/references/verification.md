# 论证与表达核验

## 算法、证明与阅读路径

以题目预期的先修知识为基准。审查者能补出解释，不等于原稿已表达清楚。

- 沿算法、引理、不变量和证明的依赖检查量词、条件、必要与充分方向、归纳、边界、交换与计数。复杂度包含预处理、查询及数据结构的最坏开销。
- 对证明疑点尝试补证或反驳，区分算法被推翻、结论成立但关键证明缺漏、合理的常规省略和尚未裁定。以预期先修知识判断哪些步骤可直接补出。
- 沿阅读顺序检查定义、转化动机、推理联系及算法与证明的对应。定位冗余、无关细节、防御性表达、记号或指代如何遮蔽核心推导或妨碍局部阅读。

指出原文、受阻步骤及其核心或局部影响，建议具体到删减、合并、移位、补定义或建立联系。不按字数、句长、措辞、重复次数或修复行数定级，也不强制顺序、图示、例子或标准算法的从零推导。适用条件、边界、易混点和诚实的不确定性说明按其信息作用判断，谨慎语气本身不是赘述。删改应保留关键前提与论证。

用题面和实现交叉核对，不默认其正确。必要的小检验使用宿主工具，有限测试不替代证明。缺少规格时只能核验内部推理，未执行的检查如实说明。

## 正文内容要求

- 正文应说明主要算法、数据结构、具体使用方式、关键转化和结论依据，给出覆盖全部约束的完整解法及复杂度分析。证明重要结论，正常先修知识和常规推导可以合理省略。
- 文字分析应独立完整。视频、代码、代码注释和外链只能补充正文，不能代替核心思路与论证。列出算法名称或贴一段可通过的程序，不等于解释了做法。
- 内容围绕题目展开，避免大量闲聊、求赞、自我介绍或与解法无关的叙事。长题面可先概括任务，不整篇复制题面，题意简述本身属于建议。
- 通常附带必要实现，核心代码片段也可满足需要。纯文字已足够清晰且实现没有额外说明价值时，可以说明不附代码的理由，不强制每篇附完整 std。

## 文字与 Markdown 要求

- 中文行文用全角中文标点并补全句末标点。中文与英文、数字和公式之间留半角空格，中文标点旁不另加空格。
- 数学量、运算式、运算符和参与运算的常数用 LaTeX，普通词语、人名、题名和算法名不用数学模式。
- Markdown 稿件用一至四级标题组织文章，不能用标题样式堆砌强调或无关内容。无序列表用列表标记，有序列表用数字加点，层级与顺序应正确显示。
- 字符串及行内程序片段用行内代码，成段代码用代码块。链接和图片使用相应的 Markdown 语法，检查渲染、图示和代码分隔是否可用。
- 一个数学表达式放在同一数学环境，独立成行的公式用行间环境。公式内部的说明文本用 `\text`，字符串用 `\texttt`。

## 数学记号要求

| 对象 | 本协议要求 |
| --- | --- |
| 赋值和推导 | 赋值使用 `\gets` 或 `\to`，因果推导使用 `\Leftarrow` 或 `\Rightarrow`，区分更新操作与逻辑关系。 |
| 判定 | 数学比较使用等于、不等于和大小关系的数学符号，不直接照搬程序的判等运算符。指示量可用艾佛森括号，并使真假取值可确定。 |
| 整数商 | 用取整符号明确整数商，例如 $\lfloor a/b\rfloor$，不能把普通分式直接当整数除法。真实的分数除法无需取整。 |
| 取模与同余 | 取模运算写作 $a\bmod b$，同余关系写作 $a\equiv c\pmod b$，不混用余数与同余关系。 |
| 结构与位运算 | 数学公式用上下标表达对象的分量，不直接写程序结构体成员。位运算用 `\operatorname{and}`、`\operatorname{or}`、`\operatorname{xor}`。集合运算改用集合语言属于建议。 |
| 上下标与大数 | 正确组织上下标，避免多字符下标或指数被拆散。大数使用科学计数法，变量名称及大小写前后一致。 |
| 复杂度 | 大 $O$ 省去常数因子，以字母表示需要单独讨论的值域、字符集等参数，不得借此删掉实际变化的参数或掩盖额外开销。 |
| 运算符与函数 | 使用正确的加减、乘除、比较、整除等数学符号。约定函数名用正体，如 `\gcd`、`\max`、`\min`、`\log`、`\det`，其他函数名用 `\operatorname` 表示。 |
| 大型运算符 | 求和、乘积、集合并交分别用相应的大型运算符，范围、对象及优先级应明确，需要时补括号。 |
| 数学结构 | 分数、根号、上划线、集合括号及其他结构使用相应数学命令，不能让排版改变表达式的含义。 |
| 省略与波浪线 | 省略号使用 `\dots`、`\cdots` 或 `\ldots`，矩阵其他方向使用 `\vdots`、`\ddots`，波浪线使用 `\sim`。 |
| 多行表达 | 连等推导用 `aligned`，分段函数用 `cases`，矩阵用 `bmatrix` 环境，正确对齐并区分各行条件。 |

以上数学记号要求适用于公式，代码块中的合法程序语法按所用语言判断，不能将程序中的取模、判等或成员访问误判为数学排版违规。

## 代码、图片与来源要求

- 代码应可读，必要时用有意义的注释解释实现，不能把核心解法只放在注释里，也不加入防抄袭干扰内容。正文中的实现应与所述算法及复杂度一致。
- 支持折叠的 Markdown 发布环境中，过长代码用折叠块展示，不能只给临时云剪贴板链接。其他材料形式应保留可读取的必要代码。
- 图示应清楚，图中文字也遵守表达要求，避免给图片额外套无关跳转链接。图片应随材料提供或使用稳定、可访问的托管地址，不依赖作者本机路径，动图或视频可作补充。
- 引用他人的文字、图片、代码或特有推导时标明来源链接并遵守已知授权条件。代码来源放在代码前属于建议。使用公认结论或标准算法本身不强制增加外链。
- 审核范围明确包含投稿来源资格时，关键思路、论证和代码不得由 GenAI 辅助产生。允许的排版、润色辅助应在文末或附录披露具体贡献，作者负责核对全部内容。此项不扩张成对其他用途或审核工具的限制。
- 来源违规须有可靠证据，不能凭文风、相同标准公式或缺少创作记录推定抄袭、未获授权或使用 AI。只取得 PDF、截图或节选时，分别说明可核验的渲染结果与无法核验的源码、折叠、授权和创作过程。

明确格式违规至少判 Major，严重妨碍辨认核心算法或证明的可判 Fatal。建议项及合理例外不直接扣分，具体定级与去重执行评分协议。
