# 格式协议

按技能入口确定是否启用格式审核。启用后检查全部适用格式类别。

先确定语言和源码／发布形式。平台专属规则是否适用由审核范围决定。相应规则未纳入范围时，图床等平台专属候选（如 `MD010`）按不适用排除。此处只审排版，数学语义、规格、教学、文风和来源资格交内容审核。

## 文字与 Markdown

| 对象 | 要求 |
| --- | --- |
| 标点与空格 | 中文叙述用全角中文标点，完整句补句末标点。中文与英文、数字、行内公式间留一个半角空格；中文标点旁不加空格，中文词内不插多余空格或全角空格。缺空格、多空格分别核对。 |
| 数学模式 | 数学量、式、运算符及参与运算的常数用 LaTeX，普通词语、人名、题名、算法名不用。同一式放同一环境，独立公式用行间环境；说明用 `\text`，字符串用 `\texttt`，合法中文说明不一律判错。 |
| 标题与列表 | 一至四级非空标题组织章节，不堆砌强调、步骤或无关内容；同组同级同用途标题统一句末标点。列表标记后留空格，有序标记用数字加点，核对嵌套、缩进、顺序和归属。 |
| 代码与链接 | 程序片段、字符串用行内代码，普通叙述用正文排版，成段代码用代码块；逐块核对代码围栏的用途。核对链接／图片语法、分隔与可用性、强调及容器定界。 |

代码块用于成段代码、伪代码、可复制的输入输出、命令、日志或需要保留原样的字面文本。把普通说明、标题、列表或公式包进围栏来装饰、突出或代替正常排版，且内容没有需保留的程序语法、字面形式或空白时，确认为滥用代码块，按 `document_layout` 记录。不能仅凭围栏数量、长度或语言标签裁定；外部评分表的对应项按[适配规则](rubric.md#外部评分表)映射。

长代码折叠为可选建议，已有折叠块仍核验语法与闭合。代码／样例／字符串空格、列表缩进、表格对齐、行尾硬换行、TeX 内部空白及渲染器数学间距不算冗余。`结论 $x$ 。` 应删标点前空格，`中文  English` 应合并边界空格。

## 数学记号

下表适用于公式，不套用于代码中的合法语法。定义、量词、取整含义、边界及论证交内容审核，根因合并见[量规](rubric.md#计分与去重)。

| 对象 | 要求 |
| --- | --- |
| 赋值、推导与判定 | 赋值用 `\gets`／`\to`，推出用 `\Leftarrow`／`\Rightarrow`，比较用数学关系符，不照搬程序判等。艾佛森括号真假值明确，单向推出不写成等价。 |
| 除法、取整、取模 | 区分分数、整数商和上下取整；取整覆盖整个所需表达式，分母非零。余数用 $a\bmod b$，同余用 $a\equiv c\pmod b$。 |
| 集合与结构 | 区分属于／包含、空集／零、开闭端点；分量用上下标，不用程序成员访问。位运算用 `\operatorname{and}`／`or`／`xor`，改用集合语言仅建议。 |
| 上下标与大数 | 多字符下标、指数正确分组，大数用科学计数法，变量名和大小写一致。 |
| 复杂度 | 时空大 $O$ 省去固定乘法因子；$O(2n)$、$O(3n\log n)$ 即使随后化简仍违规。操作次数推导可留常数；$O(1)$、$O(n^2)$、$O(2^n)$ 合法。变化的值域／字符集用参数保留真实开销。 |
| 函数与大型运算符 | 加减、乘除、比较、整除记号正确；约定函数用 `\gcd`、`\max`、`\min`、`\log`、`\det` 等正体，其他函数用 `\operatorname`。求和、乘积、并交用大型运算符，哑变量、范围、被作用项和多层依赖明确。 |
| 结构与定界 | 分数、根号、上划线、集合括号用相应命令；分组、作用域、定界匹配，不改变含义。区分绝对值、范数、整除、条件分隔，允许等价合法写法。 |
| 省略与多行 | 用 `\dots`／`\cdots`／`\ldots`、矩阵方向 `\vdots`／`\ddots`、波浪线 `\sim`。连等用 `aligned`，分段用 `cases`，矩阵用 `bmatrix`；检查闭合、换行、对齐、维度、条件和边界。 |

## 按材料用途适用的展示要求

仅核验材料实际包含的内容，不强求题解重抄题面：

- 远程评测题名通常保留原文，知名书籍译名可例外。
- 输入输出同类句式统一，并列输入变量放同一数学环境，固定输出字符串用行内代码；中文序号仅建议。
- 完整题面的取模要求在描述和输出说明两处写明且一致；缺一处重复展示算格式，模数或是否取模不明交规格审核。
- 类型放输入说明，范围通常集中于说明／提示；无部分分时可在输入格式写范围。有效位少且不小于 $10^5$ 的数用科学计数法，不同范围分公式并用全角逗号隔开，相同范围可合并。
- 实际捆绑测试须加粗声明“本题采用捆绑测试”；表格、Subtask 无序列表仅建议。计分方式未知记待核验，不自行指定。

已有规范类别优先使用，其余展示违规用 `document_layout` 提交。字段缺失、范围错误、计分歧义交规格审核；缺失声明以应出现处的标题或邻近原文绑定位置，不伪造摘录，计数按格式量规。

## 全文覆盖与候选裁定

保留候选裁定和按规范类别的覆盖表，后者记范围、依据及“已核验／未核验／不适用”，不向工具 JSON 增字段。无候选不等于类别通过；已有拒绝理由也继续全文补查。

1. 逐项阅读候选上下文。排除须说明对象、归属和允许依据，不只写“不影响理解”“独立段落”或复用无关理由。
2. 按以上所有规范补查原文，区分数学量／普通词、完整句／短标签和必要空白。图片文字、复杂宏、HTML 及渲染支持须实际取得并核查；摘录只绑定来源，不证明显示事实。
3. 补齐覆盖空项，无法取得才留未核验。记录全部发现的独立位置，达到 Fatal 后继续查其余位置和类别；工具补充项提交后合并计数。

列表归属检查前一标记、当前块和下一同级条目。`- [题目 A](链接)` 后讲 A 的“前置知识／代码讲解”及代码属于该项，应缩进或把题名改为章节；空行不改变这一关系。列表结束后真正独立的结论无需缩进，排除理由须说明归属。

同组同级同用途标题补查句末标点一致性，用 `heading` 记录偏离位置，同时引用该标题和对照标题，经 `additional_findings` 合并。

## 格式工具的覆盖与边界

Python 3.8+ 标准库脚本不编辑、不联网、不运行模型，只计算格式扣分。无 Markdown 源码不声称源码合规；源码检查也不等于页面实测。工具的扫描边界及接口见下文。

## 扫描与显示边界

格式任务已启用且可运行 Python 时使用 `scripts/format_lint.py`。类别与规则 ID 用 `--rules` 查询，`coverage` 不能作为补充发现类别。`--check` 只查环境，两者都不是稿件已通过。

工具不可用时不安装依赖，由 LLM 按相同规则核验可得材料。执行失败转为补查任务。

脚本读 UTF-8 Markdown，输出静态发现、Warning 候选及未验证范围。代码、公式、链接地址按上下文隔离，链接可见文字仍受检。

- 段内软换行按 `commonmark-softbreak-whitespace` 模型处理。可证在中文标点旁生成多余空格时，`TXT006` 为 Confirmed，证据记模型和两侧字符；其他意图不明断行留 Warning。模型推导不是页面渲染实测。
- 连续至少三条仅有编号动作句、无章节正文的标题可确认为步骤式标题；单个长标题等含糊情形留 Warning。明确更新／初始化赋值与定义、条件等式分开；定义／分类句中算法概念误用代码样式可确认，真实字符串与程序片段隔离。
- 代码围栏中的内容会被扫描器遮蔽，静态结果不判断其语义用途。LLM 须逐块对照内容与上下文核查是否滥用，确认后按上文规范以 `document_layout` 补充；对应外部评分项依量规映射。
- 宏、复杂参数、未知多字母串用途、含糊标题／强调／列表、代码字符串、词内空格及科学计数法阈值由 LLM 核验。图片、复杂 HTML 和部分容器进入 `skipped`；未知 HTML 子文字不视为已确认可见排版。
- 命令对照 [KaTeX 支持表](https://katex.org/docs/support_table.html)及[语法示例](https://katex.org/docs/supported.html)（2026-11-14），不代表洛谷当前配置实测；名称支持不证明任意参数合法。

输出 `schema_version=2`、`linter_version`、`render_model`。`findings/skipped` 为原扫描，`review_candidates` 为候选，`effective_findings/effective_skipped` 为裁定结果；`format_assessment` 对后者给出格式定级，未核验项在最终评分中的处理见[格式量规](rubric.md#格式计数与定级)，单篇 `files` 保留 `static_format_assessment`。`groups` 列类别、次数、位置、等级、扣分和证据性质。状态为 `pass/non_compliant/not_assessed`；退出码 0 只表示执行成功，2 为环境、输入或裁定错误，部分失败仍保留成功扫描。

## 来源绑定与合并

逐项裁定 `review_candidates`，静态遗漏写入 `additional_findings`，不能只写文字报告。原 Warning 类别不适用但有其他问题时，排除原候选后按正确类别补充，注明重分类关系。

临时 JSON 顶层仅 `files`，绑定本次扫描的完整 `file`、`sha256`：

```json
{
  "files": [{
    "file": "/path/to/material.md",
    "sha256": "本次扫描的摘要",
    "decisions": [{
      "candidate_id": "本次候选 ID",
      "verdict": "dismissed",
      "reason": "上下文及允许写法的规范依据",
      "evidence": [{"offset": 0, "end_offset": 2, "excerpt": "原文"}]
    }],
    "additional_findings": []
  }]
}
```

- Warning 用 `confirmed/dismissed/unverified`；scope 用 `reviewed/unverified`。未提交不默认通过；`reviewed` 只表示核查过该范围，错误仍须另补充，不能据此消除。
- 裁定理由非空，证据须为精确原文，且至少一段与候选相交。偏移是解码后 Unicode 字符的零起点左闭右开区间，不是 UTF-8 字节；剥除开头 BOM，保留 CR／LF 后算摘要。
- 补充发现含 `category, offset, end_offset, excerpt, position, standard, reason, evidence`，类别取 `--rules` 中适用项。`position` 在摘录内：缺空格取右侧起点，其他错误取错误起点，整式错误取公式正文起点。先比对静态 `occurrence_key`，同物理位置不能换锚点增次数。
- 静态 Confirmed 不能撤销；疑似误报需修复规则重扫。禁止填写 severity、次数、扣分等结果字段。

运行 `python3 scripts/format_lint.py --decisions /tmp/review.json /path/to/material.md`。脚本重扫后校验整批；旧摘要、伪造 ID、证据不符、重复裁定、非法字段均拒绝整批应用，保留静态结果并报错。JSON 校验只保证来源与计数，语义及渲染裁定仍由 LLM 负责。

## 格式任务记录

启用格式时按规范类别记录范围，逐项处理 Linter 候选和未核验范围，并补查扫描器不覆盖的类别、图片及容器。未启用记“未请求”，从审核范围中排除。

启用格式后，Linter 的每个 `review_candidates` ID 作为对应对象的 `format.<candidate_id>` 检查项，保存扫描 JSON，裁定后保存含 `effective_findings/effective_skipped` 的合并结果，用 `--format-scan` 传给覆盖工具。其他规范类别仍需单列；覆盖工具检查候选 ID、文件摘要、结果位置、剩余 Warning／未核验范围及已确认发现是否纳入任务结果，语义裁定与补充发现按格式接口提交。
