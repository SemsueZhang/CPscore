# 洛谷题解规范核对表

依据：[洛谷主题库题解规范](https://help.luogu.com.cn/rules/academic/solution-standard)及其引用的[GenAI 辅助文章写作规范](https://help.luogu.com.cn/rules/academic/ai-assisted-article-writing)，核对日期为 2026-11-13。用户要求最新规范或发现差异时回原页面确认，扣分按[评分协议](scoring.md)。

默认参照适用的内容、讲解与排版要求。图床、折叠块、投稿来源资格等平台条件按洛谷投稿场景核对，其他发布环境说明差异。提交按钮、催审期限和管理员工作流程不计入材料分，也不把 CPScore 评分当作平台采纳保证。

## 核对项目

| 原规范章节 | 审核内容与适用条件 |
| --- | --- |
| 基本规范 | 中文用全角标点，句末标点完整。数学量和表达用 LaTeX，普通词语、题名、人名及算法名不用数学模式。中西文、数字与公式间留半角空格，中文标点旁不额外加空格。 |
| 题解内容 | 文字部分应独立交代主要算法、数据结构、具体分析及关键结论的依据，解法覆盖全范围且复杂度合理。视频只能补充正文，不能代替正文。避免闲聊、求赞等无关内容，不完整复制题面。长题面附简述是建议。 |
| Markdown | 标题用 `#` 至 `####` 组织层次，避免拿标题样式充当无意义强调。无序列表用 `-`、`+` 或 `*`，有序列表用数字加点。字符串和代码片段用行内代码，成段代码用代码块，链接和图片按 Markdown 语法插入。核对渲染和资源可访问性。 |
| 公式环境 | 同一公式放在同一数学环境，独立公式用行间环境。公式内的说明文本和字符串分别用 `\text`、`\texttt`，上下标结构应明确。大数用科学计数法，大 $O$ 中省去常数因子，值域及字符集等参数以字母定义。 |
| 数学与代码记法 | 公式中使用数学记号表达赋值、比较、取整、取模、同余及位运算，不直接照搬代码运算符或结构体成员写法。赋值用 `\gets`、`\to`，逻辑推导用 `\Leftarrow`、`\Rightarrow`。取模运算用 `\bmod`，同余配合 `\equiv` 与 `\pmod`，位运算用 `\operatorname{and}`、`\operatorname{or}`、`\operatorname{xor}`。集合语言替代状态压缩中的位运算是建议。代码块中的程序语法不改写为数学符号。 |
| 数学结构 | 使用正确的分数、根号、集合、运算符与函数名，约定函数用正体，其他函数名可用 `\operatorname`。注意求和、乘积、并交、箭头、省略号和波浪线的专用记号。连等推导、分段函数和矩阵分别核对 `aligned`、`cases`、`bmatrix` 等要求。不得仅因截图无法看到源码就推定命令违规。 |
| 图片 | 图片和图中文字应清楚并符合格式要求，不用带链接的图片。洛谷投稿配图原则上使用洛谷图床，动图可按规范使用 Bilibili，核对可访问性及允许例外。不因个人美感偏好扣分。 |
| 代码 | 原则上附带实现，充分清晰的纯文字说明可有合理例外，核心代码片段也可能足够，不强制每篇题解附完整 std。长代码在洛谷投稿时用折叠块，不能用云剪贴板代替。代码应可读，不能把核心解法只写在注释中，不加入防抄袭内容。有意义的注释按需要添加。 |
| 引用 | 引用他人的内容或代码需有来源链接，并核对已知授权条件。代码来源链接放在代码前属于建议。公认结论的常规使用不等于复制他人的文字或代码，不能据此机械要求外链。 |
| GenAI | 洛谷题解投稿禁止由 GenAI 辅助产生关键思路、论证过程或代码。允许的排版、润色辅助须在文末或附录说明具体贡献。题解专门条款优先于通用文章规范中较宽的使用许可。根据作者声明或其他可靠材料判断，不能靠文风猜测。 |

公式中用分式表示整数商时要明确取整，数学上的真实除法不因此判错。省略复杂度常数因子不等于删掉本来会变化的参数，应同时核验复杂度含义与书写方式。代码可读性和实现正确性也须区分，有限执行结果不能代替一般证明。

## 要求与建议

明确格式违规至少为 Major −2，严重损坏核心算法或证明的可为 Fatal −10。建议项不直接扣分，原则性条款核对实际场景和合理例外。一般表达问题仍按核心或局部影响判断，不把所有阅读障碍都叫作格式违规。

同一根因的多处排版问题合并一次，数学错误、证明缺口与来源违规分别说明其依据。同一问题同时破坏格式和语义时只取最高级别，不能重复扣分。
