# 质量评分报告

默认在对话交付 Markdown，用户要求保存时再写文件。每题独立给出结论，篇幅围绕决定评级的理由展开，建议包含：

1. **质量等级与用途**：A+、A、B+、B、C、D、F 或 S，以及决定性理由。材料或检索不足时写“待定”及具体缺口。
2. **核心考点**：简述人类题解中的重要观察、技术路线和思考价值，注明所评解法。
3. **先例比较**：说明任务与条件对应、可复用的非平凡步骤、剩余独立亮点，附实际读到的来源。
4. **设计质量**：围绕考点、发现动机、推导联系、技术依赖和收益负担说明关键判断。A / B 重点解释是否达到加号标准；S 说明研究价值与竞赛障碍。
5. **修改建议**：只针对实际设计问题提出简洁、可执行的建议。

无需复述完整题解、输出独立求解过程或机械填写五项评分表。正文就近引用原题、题解或论文的相关章节；材料版本与评审日期记一次。

题解的写作问题与题目算法设计分别陈述，检索限制就地说明。避免为凑等级编造先例、发现动机或推导，不因显示专家能力而强行降级。

历史 `cp-novelty-review` 报告保留旧协议名称与原评级，不按字母自动换算成新等级；复用时重新依据人类题解、先例和本协议判断。
