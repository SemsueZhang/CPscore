# 洛谷评分规范

评分规范：`cpscore-difficulty-luogu-v2.3.0`。直接预测洛谷原生 1～8 档。标签名称沿用仓库已核对的 2026 洛谷体系，输出统一使用 ASCII `-`。

| level | label |
| ---: | --- |
| 1 | 入门 |
| 2 | 普及- |
| 3 | 普及 |
| 4 | 普及+/提高- |
| 5 | 提高 |
| 6 | 提高+/省选- |
| 7 | 省选/NOI- |
| 8 | NOI/NOI+/CTS |

档位是非等距的平台目标；0／未知不属八档。

按目标选手独立完成整条可靠路线的主要发现、推导、证明、知识或实现障碍判断，不逐项算分。难发现观察可主导纯思维题，复杂结构也可能直接套模板，须据具体路线说明。

## 四维分析

| 维度 | 检查内容 |
| --- | --- |
| K：知识 | 路线需要哪些先修知识及熟练程度，常用模板实际覆盖哪些部分。 |
| T：发现 | 找到关键性质、突破方向或非直接模型的障碍。 |
| R：推导 | 沿选定方向建立中间结论、衔接连续转化、补全分类与不变量，推到完整可行算法的负担，包括正确性和复杂度证明。 |
| I：实现 | 将已明确的完整算法可靠编码、调试，并处理数值、边界和资源限制的负担。 |

T 与 R 分别检查关键突破和持续推导。评估 R 时，沿必要依赖检查：即使给出关键发现，还需自行建立哪些中间结论；哪些条件或不变量必须同时保持；分支取舍、跨步骤衔接及推导受阻后的回退是否困难。缺少单个惊艳观察的路线，也可能由推导负担主导。各步局部容易理解，不代表整条路线容易独立完成；不能用 LLM 顺着题解补全推导的流畅程度代替人类选手的负担。

推导篇幅、步骤数或模型生成的思维链长度不单独决定 R。机械展开、重复计算或可直接复用的标准推导，不因写得长就加难度；短路线仍可能有难以发现的关键跳跃。四维可以相关，同一障碍不重复计数，不按维度求和、固定权重或最高值定档，也不因链长机械加档。

## 算法标签与难度判断

从实际步骤识别具体算法及目录 ID，收到的标签仍须核实；分类、语言、背景不等于必要知识。同义可统一名，`broader/context` 不能证明使用了具体子算法。

每条路线区分标准工具、自行设计的建模／状态／维护，以及可替代实现或非满分方法。工具常见不等于适用条件易发现；可由线索推出的陌生方法不强算先修。

结合相关标签选择检查重点，不机械逐项填表：

| 标签所属领域 | 重点检查的难度来源 |
| --- | --- |
| 算法基础、搜索、常见技巧 | 枚举对象、单调性、剪枝或贪心依据能否自然发现；规模与正确性是否需要关键转化。 |
| 动态规划 | 状态和转移的发现、信息是否充分、转移次序与优化依据；不能只因最后写成 DP 就认定为套路。 |
| 数据结构 | 是否只维护已确定的信息，还是需要设计非标准聚合量、合并关系、懒标记或时序不变量；模板背景与实际维护负担分别判断。 |
| 图论、网络流与匹配 | 图模型和归约的发现及等价性证明，与随后调用标准图算法的负担分别判断。 |
| 数论、组合、代数与概率 | 关键性质或恒等式是否必须作为先修知识，还是能由线索推出；检查转化动机、推导跨度、适用条件及数值处理。 |
| 字符串 | 识别匹配或结构问题、选择和组合工具的障碍，与构建自动机、维护状态等实现负担分别判断。 |
| 计算几何 | 几何关系转化、退化情形与证明，以及精度和边界处理；不能只按几何模板名定档。 |

多标签可能同属一个观察或要求独立突破，按完整路线关系判断，不按数量、最高算法档、固定权重、目录顺序、分类深度、复杂度或代码长度定档。

直接套模板、设计核心方法或完整另解绕过方法须分别分析。无已确认经验不新增“某算法至少某档”；相邻档说明具体障碍及经验适用条件。

## 替代解法检查

结合约束主动检查朴素方法、步骤简化、常见转化及绕过主要障碍的具体路线；不查本题真实标签或检索本题解法，无线索即停，不称已排除另解。

候选须有完整算法、正确性、全合法输入成本与实现条件；受限测试不替代完整依据，部分分、错解和未证实优化不降低整题难度。

按模板背景和独立发现、证明、实现的整体负担选完整路线，不跨路线拼最低门槛。快、短、知识少不等于易发现；题解省略／冗长不证明简单／困难。

另解改变档位、主要障碍或依据时，Markdown 标题后、结论前说明路线、可行性与影响；未核实则前置缺口和条件，主档仍据已核实路线，不按猜测降档。无影响可在理由简述。

## 共享目录参考

逐路线按目录 ID 读知识参考及标签样本。参考索引 0～7 经 `catalog.py levels` 映射一次为原生 1～8，输出 0 为未知，勿混淆；不另建总分。未知保留，`provisional` 不算已确认经验或固定最低档。

知识参考衡量算法学习／理解／实现负担，标签样本不证明该算法必要或代表平台条件分布。宽标签样本按题号去重，多路线难点不全归一个算法；区间主观、可未知，最高档／均值／高级名词不替代整题判断。

不读目标题缓存等级。已知题号用 `catalog.py get 算法ID --exclude-problem P题号`，隐藏相关门槛依据并重算样本；闭卷／盲评 `search/get/tag` 加 `--identity-only`，仅身份、别名、分类和算法来源。普通校准可用非目标题参考，注明范围与不确定性，不冒充闭卷。

## 经验与输出

仅用[正式经验](expert-rules.json)中 `confirmation.status=confirmed`、来源／条件／局限明确且当前匹配的规则；ID／分类仅帮助定位。原始案例、候选、目标题已知等级和 CF/AT 换算不参与主评分，非目标题样本不作固定映射。相邻档难分仍给主档及边界，不编造统计置信度。

机器输出固定为 `id, level, label, reason` 四个字段。`id` 原样绑定输入，`level` 是整数，`label` 必须与数字一致，`reason` 是非空简洁说明，可以包括不确定性；影响结论的另解或待核实候选说明放在 `reason` 开头，不新增字段。单题允许 `level=0,label=未知`，明确要求全题作答时只接受 1～8，全题覆盖。
