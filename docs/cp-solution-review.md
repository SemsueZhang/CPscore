# 标程审核

`cp-solution-review` 对照题面与给定题解，检查 std 是否正确落实约定算法，以及状态、阶段和更新依赖能否被理解。正确性、资源开销和参考代码的表达质量分别给出依据。

## 材料与调用

提供题面、约定版本的题解、完整源码，以及目标编译器、语言标准、时空限制和读写协议。缺题解或版本不明时可继续程序核验，但此时不作题解对应性核验。

```text
$cp-solution-review 对照 statement.md 和 editorial.md，审核 std.cpp 的正确性、复杂度与实现表达。
```

## 如何理解结果

采用[材料评分](README.md#材料评分)。修复行数和代码风格不直接决定级别，重点是答案、执行或理解受到什么影响。

| 级别 | 典型问题 |
| --- | --- |
| Fatal −10 | 合法输入产生错误答案，编译或协议失败，越界、溢出、不终止，或有充分依据的资源违例。 |
| Major −2 | 实现仍可正确完成任务，但核心状态、依赖、阶段或题解对应缺失，需重建主要逻辑。重要的方案、代价说明或约定交付依据问题也在此判断。 |
| Minor −1 | 主线清楚，但局部记号、接口、注释或遗留代码造成具体阅读障碍。 |

例如，更新顺序造成错误答案为 Fatal，正确更新缺少核心依赖解释为 Major，非关键注释错误为 Minor。题解本身缺证明时，std 仍按自身实现与对应情况判断。

实测结果注明环境、源码版本和覆盖范围。只要求审核时，报告提供修正建议，不直接修改原程序。

## 案例

[CSP-S 2026《迁徙》](../examples/solution-review.md)使用一份人工变体，包含 Fatal、Major、Minor 各一项独立缺陷，评分为 −3/10。案例保留给定题解、代码位置、实际反例和候选输出，展示正确性问题与说明问题如何分别扣分。

这是植入缺陷的审核示例，不表示官方 std 存在这些问题。
