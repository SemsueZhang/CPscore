# CPScore 题目难度评价现状总结

整理日期：2026-11-13。

当前采用“完整可行解法路线 + K/T/I 三维 + 洛谷八档总难度 + CF/AT 粗略参照”的评价方式。总档由规范、锚题和具体路线共同判断。平台标签换算已有冻结留出结果，整个 Skill 的难度评定准确率尚未得到独立验证。

三维规范版本为 `cpscore-difficulty-v1`，平台换算版本为 `cpscore-platforms-20261113-v1`。

## 1. 评价对象与默认背景

评价一名选手独立发现、证明并实现全数据解法的困难。默认选手未见本题或直接先例，允许竞赛常用模板。语言、模板、团队或工具条件有实际约定时，采用对应条件。

评定需要题面、约束、完整可通过解法和必要实现。只有部分分路线或关键结论尚未解决时，只给已有部分的初评与缺口，不将其当作全数据难度。

难度与材料质量、新颖度、选手水平、预计完成分钟数分别判断。算法名字、论文出处和代码行数不能直接决定难度。

## 2. K/T/I 三维各评什么

三维各用 0～5 六档，分别描述同一条完整路线的不同负担。

| 维度 | 评价对象 | 主要依据 |
| --- | --- | --- |
| K，知识门槛 | 解题前必须掌握的知识与理解深度 | 必要知识、适用条件和熟练程度。题内可推出的性质归 T。 |
| T，思维难度 | 已掌握所需知识后，发现并证明整解的困难 | 自然尝试、可用线索、关键跳跃、观察依赖和证明障碍。 |
| I，实现难度 | 已知算法和必要不变量后，正确实现的困难 | 状态维护、结构耦合、更新顺序、边界、精度和调试。 |

| 数值与标签 | K 的主要特征 | T 的主要特征 | I 的主要特征 |
| --- | --- | --- | --- |
| 0，小学 | 基本语法、算术与直接模拟 | 处理方式基本由题面给出 | 状态和边界很少的直接逻辑 |
| 1，初中 | 基础方法的基本应用 | 少量常规观察或直接转化 | 少量状态与常见边界 |
| 2，高中 | 理解并运用竞赛常用算法性质 | 非平凡转化或多个有线索的依赖观察 | 多阶段、多状态与明确不变量 |
| 3，本科 | 深入掌握高阶方法与关键性质 | 深层建模、较长推导或困难的全局论证 | 较强结构耦合与明显调试负担 |
| 4，硕士 | 专门方法或深入性质及适用条件 | 多次困难突破，或难发现的核心转化和证明 | 多个复杂结构紧密配合，精细维护负担很重 |
| 5，博士 | 训练覆盖少、理解和熟练运用均极难的专门知识 | 极难的突破或推导，需指出具体发现障碍 | 高度耦合或精细维护，正确落实本身极难 |

学段名称只是沿用标签，不代表真实学历。允许模板时，K 仍看选用和理解所需的知识，I 看实际需要编写、衔接与调试的部分。事后题解很短，也不表示 T 很低。

## 3. 总难度如何形成

总难度采用 0～7 八档，与洛谷八类难度对应。评定时比较整条路线的关键障碍与相邻档锚题，说明为什么更接近某档。

| 总档 | 洛谷名称 | 比较重点 | 当前路线锚题 |
| --- | --- | --- | --- |
| 0 | 入门 | 基础程序逻辑 | P1001 A+B |
| 1 | 普及- | 基础方法的直接应用 | P1873 砍树 |
| 2 | 普及 | 基础方法中的建模和观察 | P5019 铺设道路 |
| 3 | 普及+/提高- | 常用结构与性质的灵活运用 | P3373 线段树 2 |
| 4 | 提高 | 较深入的推导与算法配合 | P2680 运输计划 |
| 5 | 提高+/省选- | 多个关键结论形成整解 | P7077 函数调用 |
| 6 | 省选/NOI- | 深层转化、构造与证明 | P7115 移球游戏 |
| 7 | NOI/NOI+/CTS | 极难的综合突破 | P5659 树上的数 |

锚题的路线解释和来源见[三维与总难度规范](../skills/cp-difficulty-rate/references/rubric.md)。锚题及分类在规范中按 2026-11-13 的资料核对。

总档不由三维最大值、均值、固定权重或线性拉伸直接计算。同样的 K/T/I 可能压缩了不同的档内负担，允许依据路线给出不同总档，但要解释差别。当前没有唯一的 216 种三维组合到总档的已验证答案表。

存在多条可通过路线时，每条分别评三维和总档，以总难度最低的实际可行路线为主评，并保留重要替代路线。不能把不同路线各自最低的 K、T、I 拼成一个结果。路线必须满足全范围正确性、复杂度和实现资源要求。

## 4. CF 与 AtCoder Problems 的参照

CF 使用题目 `rating`。AT 使用 AtCoder Problems 社区模型的显示 `difficulty`，并非 AtCoder 官方难度。两者都与选手 rating、题目分值分别处理，相同数字不表示两站等难。

下表区间左闭右开，最后一档无上界。

| 总档 | CF 题目 rating | AT 显示 difficulty |
| --- | --- | --- |
| 0 | [800, 1000) | [0, 300) |
| 1 | [1000, 1300) | [300, 700) |
| 2 | [1300, 1800) | [700, 1300) |
| 3 | [1800, 2000) | [1300, 1700) |
| 4 | [2000, 2500) | [1700, 2300) |
| 5 | [2500, 2700) | [2300, 2500) |
| 6 | [2700, 3000) | [2500, 2900) |
| 7 | [3000, +∞) | [2900, +∞) |

更简单的题可能低于 CF 原生评级下限，不能把低于 800 的参考描述冒充官方 rating。洛谷原生 difficulty ID 1～8 对应本技能总档 0～7，ID 0“暂无评定”保留为未知。其他缺失或未定级标签同样保留未知。

AT 的 raw 值与显示值需要区分，raw 小于 400 时按下式转换：

```text
raw >= 400：display = round(raw)
raw < 400： display = round(400 × exp(raw / 400 − 1))
```

round 采用 JavaScript Math.round 对非负值的规则。例如 raw=0 显示为 147，raw=400 显示为 400。raw 可以为负，已经显示的 difficulty 不能再次转换。

这些区间是换算器的粗略分箱，不是统计置信区间、真实难度范围或官方跨站对照表。反查某一总档得到的区间，不代表该档所有题的原生值都落在其中。

有完整材料时，以内容评定为主，已核实的原生标签单列来源、日期和字段。两者不一致时解释路线瓶颈或尺度差异，不为匹配 rating 改写三维。只有平台数字时，可以给“由原生标签换算”的总档，K/T/I 保持未知。

## 5. 一次评定的顺序与交付

1. 固定材料版本、选手背景和完整可行路线，核对正确性、复杂度与实现条件。
2. 先独立给出 K/T/I 及依据，再查看外部难度标签。已知题目身份或 rating 时说明其影响。
3. 与相邻档锚题比较形成总档。多路线分别判断，必要时给主档与邻档区间。
4. 列出 CF、AT 粗略参照和已核实原生标签，注明采用的适配版本。
5. 给出判断依据和具体缺口，说明哪些事实可能改变档位。

报告至少包含题名、总档与洛谷档名、三维及理由、评分路线与复杂度、模板和语言条件、CF/AT 参照，以及判断把握和未解决事项。把握是依据是否充分的说明，不将模型自报置信度解释为概率。

调用示例：

```text
$cp-difficulty-rate 评定 statement.md，结合 editorial.md 和 std.cpp，给出知识、思维、实现、整题难度及 CF、AT 参照。
```

## 6. 当前有哪些验证依据

**三维与总档。** 当前沿用规范、路线分析与锚题评定。历史人工反馈只确认五个轴：CF946B T=0、CF643B T=1、CF1619D T=1、P3373 K=2、CF39G I=3，没有同时确认这些题的其他维度或机器给出的理由。其他历史机器草稿保留弱标签身份。

旧六档学习合成器未胜过简单基线，未被采用。当前没有经过验证的“题面到三维”学生模型或“由三维自动合成八档”的学习模型。

**平台标签转换。** 冻结同题快照保存 305 条记录，其中 303 条可用，CF 149 条、AT 154 条。开发集分别为 109、114 条，留出集各 40 条、每个洛谷档各 5 条。两站分别在开发集拟合七个严格递增切点，以总档绝对误差为目标，未在留出结果上调参。

| 来源 | 留出题数 | 总档平均绝对误差 | 完全命中 | 相差至多一档 | 最大跨档误差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| CF | 40 | 0.600 | 20/40 | 36/40 | 2 |
| AtCoder Problems | 40 | 0.350 | 27/40 | 39/40 | 2 |

这些结果只衡量原生难度标签到洛谷档次的转换。它们没有验证题面到三维、三维到总档、整个 Skill 的评级准确率或未见新技巧的评价能力。列表排序与分层选题存在取样偏差，也未证明近变体完全无泄漏。

## 7. 使用入口与维护来源

数字工具仅使用 Python 3.8+ 标准库。在仓库根目录可运行：

```sh
python3 skills/cp-difficulty-rate/scripts/platforms.py --level 4
python3 skills/cp-difficulty-rate/scripts/platforms.py --cf 2200
python3 skills/cp-difficulty-rate/scripts/platforms.py --at-raw -197
python3 skills/cp-difficulty-rate/scripts/platforms.py --luogu-id 0
```

工具只转换传入数字，不自行解题、生成三维或查询平台标签。没有 Python 时可直接按表使用。
