# CPScore 题目难度评价现状

更新日期：2026-11-14。当前入口为 `cp-difficulty-luogu`，版本 `cpscore-difficulty-luogu-v2.0.0`。

目标是利用一个前沿 LLM、简洁 Difficulty Skill 和经人类确认的专家经验，提高对未见题目的洛谷八档预测准确性。题面与完整正确解法直接得到原生 1～8 档及主要依据，0 为未知。K/T/I 保留为分析知识、思维与实现负担的概念，不强制数字化，不合成总分。CF/AT 换算工具保留在原版中，不参与主评分。

专家库目前保留五条旧单轴反馈，正式通用经验为 0 条。框架改造后，已完成一次未蒸馏 Skill 的旧 87 题配对开发诊断，未观察到增益。人类确认经验与独立评测验证其增益是两个阶段。

## 未蒸馏新版的开发诊断

2026-11-14，用 GPT-6.1 Sol high 重新运行两组各 87 题，174 次正式请求全部有效，174 个不同会话。两组同模型、同材料和参数，唯一提示差异为冻结 Skill 块，全部预测冻结后才读取标签计分。

| 指标 | 纯 LLM | 未蒸馏 Skill |
| --- | ---: | ---: |
| Accuracy | 68/87（78.16%） | 65/87（74.71%） |
| MAE | 0.2299 | 0.2644 |
| Within-one-level | 98.85% | 98.85% |
| Spearman | 0.9753 | 0.9726 |
| 平均有符号误差 | -0.0460 | -0.1034 |

两组预测不同的 11 题中，Skill 使 4 题误差减小，7 题误差增大。本轮没有胜过基线，也不能由一次实验断言稳定差异。它使用已暴露的旧 87 题，不是未见题独立测试。没有根据这些标签更新 Skill。完整结果见[实验报告](../data/difficulty/evaluations/20261114-v2-undistilled-sol-high/Report.md)。

旧 `cpscore-difficulty-v1` 及所有随包文件保持原样。历史 LuoguBench 87 题、旧锚题和已暴露标签的资料均登记为开发诊断，不能作为新版独立测试集。以下为原始记录，不是新版成绩：

## 专家与平台数据的身份

旧人工反馈只确认 CF946B T=0、CF643B T=1、CF1619D T=1、P3373 K=2、CF39G I=3，数字属于旧 0～5 轴尺度。没有同时确认其他轴、完整解释或整题等级。它们在新案例库中标为 `legacy_axis_only`，不能直接用于蒸馏已确认经验。

旧平台换算快照保留 305 条记录，303 条可用。CF 与 AtCoder Problems 的原生标签换算留出各 40 题，MAE 分别 0.600、0.350，完全命中分别 20/40、27/40。这只验证原生标签到洛谷档次的转换，不验证内容评级。旧参数、快照和复现脚本未改动，见[原版平台说明](../skills/cp-difficulty-rate/references/platforms.md)。

## 新框架的验证边界

新实验使用 `cpscore-luogu-paired-isolated-v2`，基线与 Skill 组采用同模型、生成设置、完整材料和每题独立上下文，唯一差异是冻结 Skill。指标复用 LuoguBench 实现，统一报告 Accuracy、MAE、Within-one-level、Spearman 和平均有符号误差 `prediction - truth`。此专用实验不能作为禁止额外 Skill 的官方协议提交。

独立集需在修改 Skill 前锁定，按题族隔离，标签不进入模型请求，完成全题预测后再计分。人工确认材料与家族关系，哈希和身份绑定防止冻结后串题。尚未完成家族审查的历史身份占位不能证明近变体独立。标签一旦用于诊断和更新，题目即转为开发身份。

接口、范围、身份、人工审核门槛和计分逻辑已通过 31 项基础测试，实际模型试验见上方开发诊断。下一步需要完整专家案例、新的家族隔离独立集和前沿模型的独立配对实验。不训练分类器、Ranker、专用模型，不自动调参或自动更新 Skill。
