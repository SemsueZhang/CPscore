# 数据审核

`cp-data-review` 评价测试数据和判定机制能否有效区分正确程序与错误程序。错解自身的错误程度用于解释机制，分级主要依据原集实际漏检对成绩、区分度和判定可靠性的影响。

## 材料与调用

提供题面、题解、参考程序、原测试集与答案、Checker 或 Interactor、时空限制，以及子任务、权重和分组依赖。只有生成器时，需能按原参数与种子重建原集。

```text
$cp-data-review 结合 statement.md、editorial.md 和 std.cpp，审核 data/ 原测试集与正式计分规则，给出错解成绩和补点建议。
```

## 如何理解结果

采用[材料评分](README.md#材料评分)。每项错解漏网同时需要两类证据：候选确实错误，以及在原集上实际获得了本不应取得的成绩。

报告按“确认漏检 → 确定实际影响 → 考虑错误机制 → 定级”展开，列明原集成绩、正常部分分、额外收益、相关计分单元和权重。

- **Fatal −10**：严重破坏评测可靠性。具有代表性或明确评审意义的已证错程序取得满分，是强信号。
- **Major −2**：造成明显但未达 Fatal 程度的评测失真，如多个重要计分单元漏出实质额外收益。
- **Minor −1**：已确认但影响有限的局部漏检或判定、计分问题。

不设固定分数或“过半点数”阈值。正确慢解和正常部分分不算漏洞，外加反例只用于证错与补点，不并入原集成绩。补点或判定器修订后需另行实测，同一数据根因只扣一次。

## 《地铁》案例与评分变化

[CSP-S 2026《地铁》](../examples/data-review-subway.md)记录原集 25 点、1,309,030 个询问及八项独立缺陷。按实际漏检影响复评为 −20/10，共 2 Fatal、4 Major、2 Minor。

| 机制 | 原集成绩 | 额外收益 | 复评结果 |
| --- | ---: | ---: | --- |
| 只选步行最近的进出站线路 | 8 | 4 | Minor，漏检局限于一个 4 分单元。 |
| 重复换乘边使用覆盖赋值 | 100 | 96 | Fatal，原集未区分覆盖赋值与取最小值。 |
| 用过小哨兵初始化答案 | 100 | 60 | Fatal，虽需极值组合触发，但合法边界上的满分漏检具有明确评审意义。 |

完整八项评级、反例、正确答案、实际输出和复现命令见原案例。复评分级沿用原实测事实，没有把建议补入原集后重新计算成绩。
