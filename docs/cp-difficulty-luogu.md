# 洛谷难度预测

根据同一道题的题面、约束和完整正确解法，预测洛谷原生 1～8 档难度。必要时提供实现、语言、模板和目标选手背景。

```text
$cp-difficulty-luogu 根据 statement.md、editorial.md 和 std.cpp 预测洛谷难度，简述独立完成的主要障碍。
```

核对材料一致性，以给定题解为起点，主动检查朴素方法、步骤简化及绕过主要障碍的路线。候选须核实完整算法、正确性、全范围复杂度和实现条件；不要求穷举，也不用未证实想法降低难度。按[四维分析](../skills/cp-difficulty-luogu/references/rubric.md#四维分析)比较 K（知识）、T（发现）、R（推导）、I（实现）的整体负担，再直接给出数字、档名和简洁依据。四维不要求数值或综合公式。当前评分规范为 `cpscore-difficulty-luogu-v2.3.0`。

算法标签从共享目录核对，并按各条路线区分标准工具、需自行建立的核心方法及可替代部分。结合算法领域检查四维障碍，不按标签个数、最高标签或固定权重定档；知识门槛与题目标签样本的用途及局限见[评分规范](../skills/cp-difficulty-luogu/references/rubric.md#算法标签与难度判断)。

另解改变档位、主要障碍或评级依据时，在报告开头、难度结论之前说明路线与影响。具体候选尚待核实但可能改变结论时，前置说明条件与缺口，主档仍基于已核实路线；机器输出将说明放在 `reason` 开头，保持四字段格式。

默认对象是未见本题及直接先例、允许常用模板的个人选手。看懂题解不等于独立完成；关键发现之后仍需评估推导依赖、分支与衔接负担，具体标准见四维分析。算法名称、代码长度和新颖性不能直接定档。材料不足时给 0（未知）及缺口，0 不作为有效难度标签。机器输出见[评分规范](../skills/cp-difficulty-luogu/references/rubric.md)。

只应用条件和局限明确、经过人工确认的[正式专家经验](../skills/cp-difficulty-luogu/references/expert-rules.json)，不能把题目标签当通用规则。当前收录发现与推导分离的已确认经验，不设算法固定档位。可按需用共享目录中的算法知识门槛及非目标题样本辅助校准，保留完整路线的四维独立判断。目录索引0～7与本Skill既有1～8输出须显式换算，不把入门索引0当作未知。评分时不查询目标题的真实标签；已知题号可用目录的 `--exclude-problem`，明确盲评只读 `--identity-only`；已知题目记忆可能影响判断，不能把公开旧题结果当作未见题泛化证明。

你可以直接就题目提问，再补充自己的评级、理由或相邻题比较。Skill 保留原话，将你明确给出的经验按已确认专家输入处理；已声明验证的结论不再要求验证或重复确认。模型额外归纳的扩展单列为候选，经你认可后再更新正式经验。只有等级没有理由时不虚构你的判断依据。案例与候选留在对话或仓库外开发目录，流程和记录格式见[专家反馈蒸馏](../skills/cp-difficulty-luogu/references/distillation.md)。

直接由宿主 LLM 调用，无需 Python。预测准确性需要独立评测验证。

版本记录：2026-11-16，`v2.3.0` 根据专家已验证的反馈将 K/T/I 扩展为 K/T/R/I，纠正只重关键发现、低估持续推导负担的评价偏差；输出契约与洛谷档位保持不变。本轮未运行新的独立 Benchmark。
