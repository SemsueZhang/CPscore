# 题解审核

`cp-editorial-review` 检查算法、关键结论、证明和复杂度，也检查读者能否沿着文字理解整条推导。每项意见需要说明问题在哪、为什么影响正确性或理解，以及怎样局部修订。

全程由机器判断。格式优先用随包 Python 脚本检查，不能静态确定的部分由审核 LLM 核验，再交脚本统一去重、计数和定级，没有人工复核。适用必查项仍不能确认合规就判为不合规，按 Major −2 计入“无法确认合规”；这与已证实的算法错误或格式违规分别标注。同一缺失材料导致的后果合并，工具不可用本身不扣分。

内容审核与格式审核分别完成、分别给结论后再合并总分。内容必须覆盖数学正确性、证明完整性、文字样例过程、人类思维与阅读体验、冗余和题外内容，不能用脚本候选或格式扣分代表内容已审。每篇强制检查人类思维：原文存在难以理解或无法沿阅读顺序重建的推导时，直接 Fatal −10，指出具体受阻步骤；数学结论正确、审核者能补出或局部能修好均不降级。算法本身的难度和合理先修知识不因此受罚。

## 材料与调用

提供完整题解、题面与约束，附上题解声明正确的实现。多种做法都作为正确解交付时，应一并提供。审核投稿规范或来源资格时，还需明确目标规范和相关材料。

```text
$cp-editorial-review 结合 statement.md 审核 editorial.md，给出评分、依据与修改建议。
```

## 如何理解结果

采用[材料评分](README.md#材料评分)，区分算法错误、证明缺漏、表达障碍和适用规范问题。

| 情况 | 判断方式 |
| --- | --- |
| 算法或关键结论被反例、有效论证推翻 | 按 Fatal 判断，保留反例或反驳。 |
| 缺少关键正确性、最优性或复杂度依据，但未造成难以理解的推导 | 按 Major 判断，必要补证完整写出并标明来自审核者，不能仅因缺证明判算法错误。 |
| 读者需重新发现非平凡联系、重组推导才能理解 | 人类思维检查直接判 Fatal，区分推导难懂与算法错误。 |
| 未违反明确格式要求的局部说明或阅读问题 | 依影响判断 Minor。 |
| 公认结论、常规推导的合理省略或允许的等价表达 | 不因省略或风格不同扣分。 |

正文完整性、Markdown、数学记号、代码、图片和来源要求均按实际审核范围参与评分。同一格式类别按单篇独立位置计数：1～2 处为 Major −2，至少 3 处为 Fatal −10，同类只扣一次。建议项不算已证实次数。审核者补出的证明应标为补证，不能当作原稿已有内容。

审核先逐项定位问题，再归并计分。发现足以拒绝的错误后，仍检查其余适用项；报告保留各类具体依据，不用“数学排版不规范”代替不同问题。符号核验也检查函数、聚合量和求和范围的含义，不能只改记号外观。源码与渲染分别说明检查范围，无法取得目标页面时注明替代渲染或未核验部分。

内容合规独立检查涉黄、涉赌、涉毒及危害国家安全等内容，依据具体语境和适用投稿条款判断，不以关键词替代证据。格式脚本区分缺空格、多空格与必要空白，检查可执行的公式样式规则。定义、运算范围与论证的数学含义仍由 LLM 核验，不能重复包装成格式扣分。

教学评价使用三种方法：沿实际阅读顺序检查定义、动机和逻辑联系；对可疑冗余尝试删除，核对是否损失信息；对确认的问题比较局部改写，只有理解体验实际改善才提出必改意见。必要的边界解释、严格证明、有价值的错误路线和简洁完整的文章都不因篇幅或个人文风受罚。不检测 AI 作者身份，明确适用的投稿来源资格另行取证。

所有文字样例和演示按初始状态、每步操作、状态更新、中间值及结果逐步核验。程序通过样例不能代替核对解释过程。全文首尾、标题、附注、图片和代码注释也要检查求赞、求通过、自我介绍、闲聊、广告及无关叙事。报告分别给出内容和格式结论；无问题时仍概述实际核验依据，不强行删改。

另有评分表时，按具体证据与得分点的实质对应计分，不因名称不同漏算已明确指出的等价问题，也不把笼统批评视为命中全部细项。外部评分与 CPScore 材料评分分别说明。

## 格式脚本

题解与题面使用同源的格式脚本和[格式协议](../skills/cp-editorial-review/references/format.md)，共享类别、计数、复核接口和扣分标准。两个技能分别随包提供文件，均可单独安装。

已有 Python 3.8+ 和命令执行能力时，先检查环境，再扫描 Markdown：

```sh
python3 skills/cp-editorial-review/scripts/format_lint.py --check
python3 skills/cp-editorial-review/scripts/format_lint.py editorial.md
python3 skills/cp-editorial-review/scripts/format_lint.py --decisions /tmp/review.json editorial.md
```

只使用标准库，不调用模型或修改原文。LLM 对 `review_candidates` 给出有证据的裁定和补充发现，脚本验证文件、摘要、候选 ID 与精确摘录，再计算格式扣分。原始扫描与生效结果均保留。接口说明见[格式复核协议](../skills/cp-editorial-review/references/format.md#llm-格式复核接口)。一次命令可传多个文件，但次数按每篇单独统计，不跨文章凑够三处；重复路径及重复位置不会增加次数。

LLM 负责脚本未覆盖的原文，不以出现候选为补查前提。允许新增及重新归类：原警告类别不适用但另有问题时，排除原警告并通过 `additional_findings` 提交正确类别及证据，不能只撤掉警告而漏报新根因。语义、证明和教学问题继续列在内容审核中，同根因最后取最高级别扣一次。

正文和公式边界缺空格属于同一类别。若正文缺一处、公式边界缺两处，合计三处，判 Fatal −10；缺空格与多空格分别计算。只有 Confirmed 计入三处阈值，三条 Warning 不等于三处确定错误。

已实现间距、中文引号等标点、明确句式的句末标点、段内软换行、标题／列表／代码结构，以及可识别的数学环境、正体函数、运算符、省略号和复杂度常数等规则。v2.1 增加连续动作标题、明确赋值和拆分公式检查，识别列表标记宽度对应的合法缩进和无空行续行，避免链接地址、行内代码内容干扰句末判断。

v2.3 将规则和实现抽为共用源，纳入适用的输入输出、范围和子任务展示约定。`DOC001` 由审核 LLM 通过补充发现接口核验，不代表这些要求已能静态自动裁定。平台专属图床限制也须先确认适用性。

含糊用法保留 Warning，图片文字、复杂 HTML 等范围标为未验证，交审核 LLM 核查。未提供裁定或仍无充分证据的范围继续按严格通过策略处理。软换行只有在当前 CommonMark 空白模型下能证实产生中文标点旁多余空格时才确认为违规，并输出两侧字符和模型。JSON 的 `linter_version` 标识实现版本，`render_model` 标识模型，均不代表完成了目标页面实测。规则表可运行 `--rules` 查看，边界见技能 Reference。

无 Python 或扫描失败时不安装环境，LLM 继续检查可取得的材料，并按相同规则记录格式证据和位置。只有未完成的必查范围才按材料或核验缺口计 Major，截图不能证明源码合规。退出码 0 仅表示执行成功，不代表合规；失败为 2，批量部分失败保留成功文件结果。复核记录有误时整批不应用，不能产生假通过。

十篇材料的漏检原因、前后对照及重跑方法见[格式漏检复盘](../tests/editorial/format-regression.md)。这次回归只验证具体规则和计数，不当作独立质量评测。

两例用于理解证明缺漏及补证，未演示新版协议的全部规范核验，不将旧评分当作已完成新版全项复审。

新增[教学对照材料与检查说明](../tests/editorial/README.md)，包含清晰原稿、防御性变体、动机缺失、机械重复和简洁完整版本。它们是自建合成案例，不是人类专家校准的 Gold，也不是独立效果评测。
