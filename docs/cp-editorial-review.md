# 题解审核

提供题面、全部约束、完整题解及所有附加方案，注明目标读者和投稿规范。

```text
$cp-editorial-review 结合 statement.md 审核 editorial.md，给出评分、依据和修改建议。
```

报告总评先给 AIGC 裁定，再给合规结论、10 分制评分及档次，随后按“内容问题”与“格式问题”列出全部已确认问题；无问题的类别不列空清单，也不重复列核查项、通过项或未发现问题。确认一项错误后仍继续完成其余核查，内部覆盖记录用于查漏，去重计分并保留各处证据。

只依原稿裁定，不代补条件、算法或关键证明。稿内题意转述、约束、取模和复制样例须与原题对照。部分分按声明范围判断，超时、卡常等方案仍检查正确性；未经核实的通过记录和失分原因注明作者自述。检查正文能否讲清目标、方法用途与答案的联系，代码或操作提纲不能替代核心讲解。

完整审核执行两遍，每遍覆盖内容、文风和格式，静态核对每份代码并手算样例。两遍发现取并集，按根因合并计分，保留证据与发现遍次，不自动编译运行。每项问题给级别、位置、短摘录、失效依据和影响，并同时给出该处的具体修改方向及今后写作时避免同类问题的方法；相同根因或方法可合并，保留各处证据。仅在未核实范围影响结论时说明。只审核时不修改原稿，重审说明结论变化。

循环说明与信息倒置纳入文风分类。每次按[文风分类](../skills/cp-editorial-review/references/ai-style-patterns.md)逐类裁定，确认任一类即在总评首句写 **“本文为 AIGC”**，无需另找生成记录；未确认时写“未检出明显 AIGC 文风”，未核验范围仅在影响裁定时说明。对外只列确认的文风问题，给类别、级别、位置、短摘录、影响范围、机制及修改建议；每类至少 Major，广泛影响阅读或阻断核心理解时 Fatal，标签本身不另扣分。标题、加粗、列表或数学错误本身不触发 AIGC。内容、文风与格式按[评分协议](../skills/cp-editorial-review/references/scoring.md)去重。

格式脚本可在仓库中运行，安装后使用对应 Skill 内的路径：

```sh
python3 skills/cp-editorial-review/scripts/format_lint.py editorial.md
```

LLM 须逐项裁定候选，并按全部规范类别补查全文、记录覆盖状态；排除理由应说明上下文与允许依据，尤其核实列表正文归属及同组标题标点。按[格式协议](../skills/cp-editorial-review/references/format.md)合并全部独立位置，同类 1～2 处 Major、至少 3 处 Fatal。没有 Python 时继续核验，不因工具故障扣稿件分；静态检查不代表编译、评测或页面渲染通过。
