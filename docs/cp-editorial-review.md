# 题解审核

`cp-editorial-review` 检查算法、关键结论、证明和复杂度，也检查读者能否沿着文字理解整条推导。每项意见需要说明问题在哪、为什么影响正确性或理解，以及怎样局部修订。

## 材料与调用

提供完整题解、题面与约束，附上题解声明正确的实现。多种做法都作为正确解交付时，应一并提供。审核投稿规范或来源资格时，还需明确目标规范和相关材料。

```text
$cp-editorial-review 结合 statement.md 审核 editorial.md，给出评分、依据与修改建议。
```

## 如何理解结果

采用[材料评分](README.md#材料评分)，区分算法错误、证明缺漏、表达障碍和适用规范问题。

| 情况 | 判断方式 |
| --- | --- |
| 算法或关键结论被反例、有效论证推翻 | 按 Fatal 判断，保留反例或反驳。 |
| 缺少关键正确性、最优性或复杂度依据 | 按 Major 判断，尝试补证，不能仅因缺证明判算法错误。 |
| 读者需重新发现关键联系、重组核心推导 | 按重要理解障碍判断。 |
| 未违反明确格式要求的局部说明或阅读问题 | 依影响判断 Minor。 |
| 公认结论、常规推导的合理省略或允许的等价表达 | 不因省略或风格不同扣分。 |

正文完整性、Markdown、数学记号、代码、图片和来源要求均按实际审核范围参与评分。明确格式违规至少为 Major，严重损坏核心算法或论证的可为 Fatal，建议项与合理例外不直接扣分。审核者补出的证明应标为补证，不能当作原稿已有内容。

## 案例

- [《货币系统》](../examples/editorial-review.md)：只证明系统等价，未给出不可约面额必选的核心下界，演示评分 8/10。
- [CCPC 2026 长春 L《故事》](../examples/editorial-review-story.md)：从最少剩余的 1 到最终最短长度，还缺少端点保留判定，旧版数学审核评分 8/10，附补证与有限核验。

两例用于理解证明缺漏及补证，未演示新版协议的全部规范核验，不将旧评分当作已完成新版全项复审。
